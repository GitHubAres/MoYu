- **版本**：V1.0（草案）
- **日期**：2026-10-02
- **目标版本**：墨语MoYu V1.5.0（公告模块随下一版本发布）
- **前置状态**：V1.4.0 已由 Codex 开发完成
- **约束**：本计划书只做设计，不改代码

---

## 1. 背景与目标

### 1.1 背景
墨语MoYu 是本地优先的 AI 小说写作工作台（FastAPI + SQLite + 静态前端，本地 8321 端口）。目前已具备更新检查（`GET /api/update/check`，拉取 GitHub Releases manifest）与许可证联网校验的成熟"联网降级"模式，但**缺少面向用户的运营触达能力**——版本更新说明、使用技巧、活动通知等无法送达已安装用户。

### 1.2 目标
实现**公告模块**：用户启动/访问应用时，首先弹出公告页，确保重要信息 100% 触达；同时提供不打扰的"公告中心"供随时回看。

### 1.3 成功指标
- 公告触达率（弹窗曝光）≥ 95% 启动会话
- 公告关闭/确认流程零报错、零白屏
- 完全离线环境下功能静默降级，不影响写作主流程

## 3. 整体方案

### 3.1 内容来源策略（双通道 + 本地缓存）

```
启动时
  │
  ├─ 1. 后端 GET /api/announcements/latest
  │      ├─ 尝试远程源（announcement.json，GitHub Releases 同域托管 或 moyu-cloud /v1/announcement）
  │      │     超时 5s，成功 → 写入本地缓存表 + 返回
  │      ├─ 失败 → 读本地缓存（上次成功的远程内容）
  │      └─ 无缓存 → 读应用内置 static/announcements/builtin.json
  │
  └─ 2. 前端拿到公告 + 用户确认状态 → 决定是否弹窗
```

理由：与现有 `update.py` 的 manifest 拉取模式完全一致，无新增外部依赖；离线用户至少能看到随版本内置的公告（如版本更新说明）。

### 3.2 模块划分

| 层 | 新增内容 | 说明 |
|---|---|---|
| 后端 | `app/api/announcement.py` | 路由：`GET /latest`、`GET /`（列表）、`POST /{id}/ack` |
| 后端 | `app/db.py` 新增两张表 | `announcements`（内容快照）、`announcement_acks`（用户确认记录） |
| 前端 | `static/js/pages/announcement.js` | 公告浮层组件 + 公告中心页面（`#/announcements` 路由） |
| 前端 | `static/js/app.js` 启动流程插入 | settings 加载后、router 启动前触发公告检查 |
| 内置数据 | `static/announcements/builtin.json` | 随版本打包的内置公告（PyInstaller 需确认包含） |
| 远程数据 | GitHub Releases `announcement.json`（推荐） | 复用 manifest 托管方式，零服务端成本 |

## 4. 详细设计

### 4.1 数据模型（SQLite）

```sql
-- 公告内容快照（远程/内置统一落到本地，前端只读本地）
CREATE TABLE IF NOT EXISTS announcements (
    id            TEXT PRIMARY KEY,          -- 远程为 'remote-<uuid>'，内置为 'builtin-<slug>'
    source        TEXT NOT NULL,             -- 'remote' | 'builtin'
    level         TEXT NOT NULL DEFAULT 'normal',  -- 'normal' | 'force'
    title         TEXT NOT NULL,
    body_md       TEXT NOT NULL,             -- Markdown 子集
    link_url      TEXT DEFAULT '',
    link_text     TEXT DEFAULT '',
    version_tag   TEXT DEFAULT '',           -- 关联版本，如 '1.5.0'
    starts_at     TEXT DEFAULT '',           -- 生效时间（ISO8601，空=立即）
    ends_at       TEXT DEFAULT '',           -- 失效时间（空=长期）
    fetched_at    TEXT NOT NULL,             -- 快照拉取时间
    content_hash  TEXT NOT NULL              -- 去重/变更检测
);

-- 用户确认记录（同一公告只记一条）
CREATE TABLE IF NOT EXISTS announcement_acks (
    announcement_id TEXT PRIMARY KEY REFERENCES announcements(id),
    acked_at        TEXT NOT NULL,
    ack_type        TEXT DEFAULT 'view'      -- 'view' 自动看过 | 'confirm' 手动确认 | 'dismiss_forever' 不再显示
);
```

说明：`force` 级别且未过期的公告，即使 acked 为 `view` 也继续弹，直到 `ends_at` 或用户选 `dismiss_forever`。

### 4.2 后端 API

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/announcements/latest` | 返回当前应展示的公告（含 `acked` 状态、生效/失效过滤、force 逻辑由前端据 `level`+`acks` 判断，后端原样返回字段） |
| `GET` | `/api/announcements` | 全部公告列表（公告中心用），按 `fetched_at`/`starts_at` 倒序，带 ack 状态 |
| `POST` | `/api/announcements/{id}/ack` | body: `{ack_type}`，写入确认记录 |

拉取流程（写在 `announcement.py` 内部，跟随 `update.py` 的风格）：
1. 读 `app_settings.announcement_url`（默认指向 Releases `announcement.json`，可在设置中改）
2. httpx 5s 超时拉取 → 校验 schema（pydantic）→ 与本地 `content_hash` 比对，有变化则 upsert 快照
3. 任何异常：log debug 级日志，静默返回本地最新快照
4. 全空：fallback 到 `static/announcements/builtin.json`

### 4.3 远程 announcement.json 格式

```json
{
  "id": "2026-10-v150-release",
  "level": "normal",
  "title": "墨语 V1.5.0 更新公告",
  "body_md": "## 新功能\n- 公告模块上线……",
  "link_url": "https://github.com/GitHubAres/MoYu/releases",
  "link_text": "查看完整更新日志",
  "version_tag": "1.5.0",
  "starts_at": "2026-10-10T00:00:00+08:00",
  "ends_at": "",
  "min_app_version": "1.4.0"
}
```

`min_app_version`：低于该版本的客户端忽略此公告（与 `update.py` 的 `CURRENT_VERSION` 比对），避免老客户端解析不了新格式。

### 4.4 前端设计

**启动插入点**（`app.js`，现有 boot IIFE 内、`router.start()` 之前）：

```js
(async function () {
  // ...现有 settings/theme 加载...
  try { await announcement.checkOnBoot(); } catch (e) {}  // 失败绝不阻塞主流程
  router.start();
})();
```

`checkOnBoot()` 行为：
1. `api.get("/announcements/latest")`
2. 无公告 / 公告未生效 / 已过期 → 返回
3. `level=normal` 且存在 ack → 返回
4. 否则渲染公告浮层，挂到 `#modal-root`，**z-index 高于一切现有弹窗（z-[95]）**

**公告浮层结构**（遵循现有 `ui.confirm` 视觉体系：surface-container-lowest 卡片 + ink-black/40 遮罩）：
- 顶部：级别徽标（`force` 显示"重要公告"）、标题、`version_tag` 小字
- 中部：正文区域（Markdown 渲染，见 4.5），固定最大高度可滚动
- 底部：`了解更多`（若有 link）+ 主按钮（normal 为「我知道了」/ force 为「知道了，本次不再提示」+ 次按钮「7 天内不再显示」）
- 交互：Esc 关闭 ≡ normal 的确认；遮罩点击不关闭 force 公告（防误触）

**公告中心**：`#/announcements` 路由，复用列表页样式（参考 `versions.js` 的快照列表），每条显示标题/日期/已读状态，点击展开正文。入口放在侧边栏底部「公告」项 + 书架页顶栏图标（具体位置实现时与现有导航对齐）。

### 4.5 Markdown 渲染与安全

- vendor 目录当前只有 tailwind.js + fonts，**不引入 marked.js 等新依赖**（打包需本地化，增加体积）
- 实现一个 200 行内的迷你渲染器：仅支持 `##/###`、`-` 列表、`**粗体**`、段落、链接；其余字符全部 HTML 转义
- 所有 URL 仅允许 `https:` 协议（`javascript:` 等直接剥除），`target="_blank" rel="noopener"`
- 渲染前先经后端 pydantic 校验长度上限（title ≤100 字，body ≤ 5000 字）

## 5. 兼容性与打包注意事项

1. **PyInstaller**：`static/announcements/builtin.json` 需在 `moyu_entry.spec` 的 datas 中确认包含（参照现有 static 打包配置）
2. **offline 首启**：远程、缓存均无 → 内置公告兜底，保证新装用户看到 V1.5.0 更新说明
3. **降级**：老版本客户端无此模块，不受影响；新模块所有失败路径静默，不弹错误提示、不阻塞 router
4. **深色模式**：浮层全部使用 design token 颜色类（`bg-surface-*`、`text-on-*`），自动适配
5. **测试**：沿用 `tests/` 现有 pytest 风格，新增 API 用例（拉取成功/超时/格式错误/ack 幂等/force 逻辑），目标新增 ≥8 条用例

## 7. 验收标准

1. 全新安装启动 → 弹出内置公告，确认后重启不再弹（normal）
2. 远程 announcement.json 更新后重启 → 弹出新公告
3. 断网启动 → 展示上次缓存公告；无缓存 → 展示内置公告；全程无报错
4. force 公告每次启动都弹，「7 天内不再显示」生效，过期后自动消失
5. 公告正文注入 `<script>` / `javascript:` 链接 → 被转义/剥除，无 XSS
6. `pytest -q` 全绿（含新增用例），`python build_exe.py` 打包后实测通过

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 远程源被篡改注入恶意内容 | 仅 HTTPS；正文白名单渲染 + 协议白名单；长度限制 |
| 拉取慢阻塞启动 | 后端异步 5s 超时；前端不 await 渲染完成才启动 router（先弹骨架或先启动后弹） |
| 用户嫌弹窗烦 | normal 级只弹一次；force 提供"不再显示"出口；设置中预留「公告偏好」扩展位 |
| 多公告并发 | 本期只弹最新一条，其余进公告中心，实现复杂度可控 |
