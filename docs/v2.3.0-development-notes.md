## 一、 版本迭代背景与目标

依据签约网文作家在 VPS 生产环境（Linux/Debian, Python 3.14 + FastAPI + SQLite3）的实机全流程创作体验，针对“长篇网文工作流资产反哺入库存在格式污染、分卷重复、方法论外泄，以及正文 AI 续写战力境界与金手指脱节”等痛点，进行了专项架构重构与交互闭环升级。

---

## 二、 新增与优化功能模块清单

### 1. 故事大纲与分卷反哺清洗去重机制
- **模块路径**：`app/workflow_assets.py`、`app/services/plot_service.py`
- **核心能力**：
  - 引入 `normalize_title()` 标点符号与 Markdown 加粗清洗算法，剔除 `**`、`#`、冒号与空格等格式干扰。
  - 在大纲三位一体同步函数 `batch_sync_triad_assets()` 中引入卷前缀模糊比对，彻底解决同一卷名因格式微差产生重复分卷或分卷嵌套的异常。

### 2. 实体设定库（万相谱）防污染过滤器
- **模块路径**：`app/workflow_assets.py`
- **核心能力**：
  - 增加 `METHODOLOGY_KEYWORDS` 拦截器，自动识别并拦截非小说世界观的创作技巧说明（如《黄金三章节奏法则》、《前三章钩子》、《核心看点说明》等），严禁其作为 `category='term'` 污染小说实体词典。

### 3. 主角战力与金手指数值状态板（升级流闭环）
- **模块路径**：`app/api/protagonist.py`、`app/services/context_service.py`
- **核心能力**：
  - 提供 `GET/PUT /api/works/{work_id}/protagonist` 接口，精准管理主角姓名、当前修为境界、金手指名称与推演进度、关键资源（丹药/寿元/法宝残卷）、现阶段核心目标与矛盾。
  - 在正文创作上下文装配链路 `assemble_writing_context()` 中，置顶优先注入【主角战力与金手指状态板】，确保 AI 正文续写严格锚定主角战力数值与即时目标，杜绝战力崩坏。

### 4. 前端交互体验重构（分组勾选与书斋状态卡）
- **模块路径**：`static/js/pages/workflows.js`、`static/js/pages/workbench.js`
- **核心能力**：
  - **工作流反哺弹窗**：在万相谱、故事大纲、剧情时间线、伏笔计划表分组增加独立 `[全选]`、`[全清]` 开关；在实体库增设 **「🎯 核心优先」** 智能过滤，自动保留主角与法宝，过滤跑龙套条目。
  - **工作台书斋抽屉**：右侧上下文抽屉常驻显示主角战力卡片，并支持快捷唤出 `openProtagonistModal` 进行实时数值更新。
