## 一、现状诊断与痛点归纳

在 v1.9.0 完成功能去重与数据库外键打通后，系统进入了“单点可用”阶段，但暴露了深层次的工程设计痛点：
1. **共享契约缺失**：
   - 核心数据模型无单一真实来源（Single Source of Truth），各个 API 与资产抽取器各自定义局部结构（如 `timeline_events` 在 `workflow_assets` 中完全遗漏，伏笔和细纲缺少节点与父子关系字段）；
   - `workflow_runs` 仅绑定 `chapter_id`，脱离大纲节点，无法感知目标大纲上下文。
2. **统一状态流缺失**：
   - 后端各模块直连 SQL，缺乏统一的领域服务（Service Layer）与上下文组装器；
   - 前端各页面各自闭包存状态，页面间缺乏全局 Store 与事件总线，跨页面资产互通全靠被动刷新。
3. **协作验收机制缺失**：
   - 过去测试仅验证接口返回 200，未覆盖跨功能协作闭环（工作流推演 → 采纳写入 → 大纲/时间线/伏笔/写作台多端联动感知）。

---

## 二、重构总体方案设计

本次重构确立“契约优先、服务下沉、前端统一、链路闭环”的架构原则：

```
       ┌────────────────────────────────────────────────────────┐
       │              共享领域契约 (Shared Contracts)            │
       │   - PlotTriadContract (Outline, Timeline, Foreshadow)  │
       │   - WorkflowAssetContract (Structured Extraction)       │
       └───────────────────────────┬────────────────────────────┘
                                   │
              ┌────────────────────┴────────────────────┐
              ▼                                         ▼
┌───────────────────────────┐             ┌───────────────────────────┐
│     后端统一服务层        │             │      前端统一状态层       │
│  (app/services/)          │             │    (static/js/store.js)   │
│ 1. plot_service.py        │             │ 1. store.plot (三位一体)  │
│    - 三位一体统一读写与聚合│             │ 2. store.work (当前作品)  │
│ 2. context_service.py     │             │ 3. store.events (事件总线)│
│    - 全局统一上下文拼装器 │             │    - PLOT_UPDATED         │
└─────────────┬─────────────┘             └─────────────┬─────────────┘
              │                                         │
              └────────────────────┬────────────────────┘
                                   ▼
        ┌─────────────────────────────────────────────────────┐
        │       端到端跨模块协作验证 (Collaboration E2E)       │
        │   工作流启动(带大纲) ➔ 推演提取 ➔ 一键采纳 ➔          │
        │   大纲树更新 + 时间线入库 + 看板入库 + 写作台实时感知   │
        └─────────────────────────────────────────────────────┘
```

## 三、执行落地与架构变更详情

### 阶段一：后端共享契约与服务层沉淀 (Backend Domain Services)
1. **数据库迁移 Migration 17 (`app/db.py`)**：
   - 为 `workflow_runs` 表添加 `outline_node_id INTEGER REFERENCES outline_nodes(id) ON DELETE SET NULL`；
   - 增加索引 `idx_workflow_runs_outline_node`。
2. **统一剧情三位一体领域服务 (`app/services/plot_service.py`)**：
   - 封装三位一体核心领域操作：
     - `get_node_plot_summary(work_id, node_id)`：获取大纲节点聚合摘要（梗概 + 时间线 + 伏笔）；
     - `add_timeline_event(work_id, data)` 与 `add_foreshadow(work_id, data)`；
     - `batch_sync_triad_assets(work_id, ...)`：提供批量原子化采纳写入。
3. **统一上下文装配服务 (`app/services/context_service.py`)**：
   - 统一工作流（Workflow Engine）与写作台（Chat/AI Tasks）的上下文拼装规范：
     - 自动拼装：作品基底 + 章节前情 + 目标大纲节点剧情卡（梗概/绑定事件/关联伏笔）+ 设定实体与羁绊关系。
4. **工作流资产交换契约补齐 (`app/workflow_assets.py`)**：
   - 新增 `AssetTimelineEventIn` 结构，补齐时间线事件提取器；
   - `AssetForeshadowIn` 补充 `outline_node_id`；
   - `AssetOutlineIn` 补充 `parent_id`；
   - `SyncAssetsIn` 包含 `timeline_events`；
   - `sync_assets_to_database` 委托 `plot_service` 统一入库。

---

### 阶段二：前端统一状态层与事件总线 (Frontend Store & Event Bus)
1. **新建客户端统一 Store (`static/js/store.js`)**：
   - **`store.work`**：管理当前作品元数据；
   - **`store.plot`**：统一缓存与管理大纲树、时间线列表、伏笔列表，提供 `refresh(workId)`；
   - **`store.events`**：轻量发布/订阅事件总线：
     - 发布 `plot:changed`、`entity:changed` 等统一事件。
2. **接驳各页面数据流**：
   - `outline.js`, `timeline.js`, `board.js` 监听 `plot:changed`，感知更新自动局部重绘；
   - `workflows.js` 采纳资产后触发 `store.events.emit('plot:changed')`；
   - `index.html` 引入 `store.js`。

---

### 阶段三：工作流与三位一体端到端功能联动 (Workflow Triad Integration)
1. **工作流启动交互扩展 (`app/api/workflows.py` & `static/js/pages/workflows.js`)**：
   - `RunStartIn` 接受 `outline_node_id`；
   - 运行工作流弹窗中增加「关联大纲节点」下拉选择框；
2. **工作流执行引擎接入 (`app/workflow_engine.py`)**：
   - 调用 `context_service` 自动装载大纲剧情脉络卡；
3. **工作流确认与资产采纳弹窗扩展**：
   - 新增【时间线事件】卡片展示与勾选采纳；
   - 伏笔与细纲卡片明确标注关联的目标大纲节点。

---

### 阶段四：端到端协作链条验收与部署上线 (Verification & Deployment)
