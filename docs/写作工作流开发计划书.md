## 1. 背景与目标

### 1.1 背景

墨语现有的 AI 创作能力是**单点式**的：写作工作台里一次选一个任务（续写/扩写/润色…）、选一个 Skill、生成一次、预览采纳。实际长篇创作是**链式**的——比如「一章的标准生产流程」可能是：

> 回顾上一章结尾 → 生成本章草稿 → 一致性检查 → 按检查意见修订 → 润色定稿 → 提取剧情事件入时间线 → 更新本章概要

目前这条链路全靠作者在多个页面间手动反复操作，步骤一多就烦、容易漏。而墨语已经有全部零部件：

| 现有资产 | 在本功能中的角色 |
|---|---|
| **Skill 市场**（`skills` + `skill_files` 表，`build_skill_system_prompt` 装配器） | 工作流**每个步骤的执行核心**——步骤即 Skill 调用 |
| **AI 任务中心**（`ai_tasks` 台账 + 任务页） | 步骤级与运行级进度追踪、日志、重试的既有范式 |
| **`/api/ai/generate`**（流式 SSE、多候选、长度档位） | 步骤执行引擎，直接复用 |
| **版本快照 / 一致性检查 / 时间线** | 工作流步骤可挂载的下游动作（后续里程碑） |

### 1.2 目标

实现**小说写作工作流**：作者把常用创作流程编排成**可编辑的步骤序列**并一键运行。运行器逐步调用对应 Skill，步骤之间传递上下文，关键节点支持**人工确认闸**——所有 AI 产出先预览、由作者确认后才继续或入库，绝不静默写入正文。

### 1.3 成功指标

- 一个 ≥3 步的内置示例工作流开箱即可运行，全程零报错
- 工作流 CRUD、排序、启停、复制与 Skill 市场交互 100% 通过回归测试
- 运行中断（关窗/重启/AI 失败）后可恢复查看状态，可重跑失败步骤
- 人工确认闸 100% 生效：未经确认的任何步骤输出不得写入正文

## 3. 整体方案

### 3.1 核心设计原则

1. **步骤 = Skill 调用**。不重写提示词装配，不绕开 Skill 市场；工作流只是给 Skill 序列加上「输入从哪来、输出给谁、何时停下来等人」的编排语义。
2. **纯编排、薄引擎**。运行器只做三件事：准备上下文 → 调现有 AI 链路 → 记录结果并决定是否暂停。AI 调用本身零新增代码路径。
3. **内容安全红线不变**。确认闸是数据模型一等公民（`requires_review` 字段），引擎在步骤完成时强制检查，未确认不得推进到「已采纳」状态，任何路径不直接写正文。

### 3.2 数据流

```
[工作流运行页] 选择作品/章节 → POST /api/workflows/{id}/runs
        │
        ▼
后端运行器（asyncio 后台任务）
  │  ① 载入 workflow_steps，渲染每步输入：
  │     步骤上下文 = 章节正文 / 前序步骤输出（{{steps.N.output}}）
  │     → 注入 {{context}} / {{instruction}} 占位符
  │  ② 调 build_skill_system_prompt(skill_id, ...)  ← 现有装配器
  │  ③ chat_stream / chat（流式）→ 该步 ai_tasks 台账
  │  ④ requires_review ? 置 awaiting_review，挂起运行
  │     : 记录输出，进入下一步
  ▼
[运行视图] 轮询 /api/workflows/runs/{run_id}（或 SSE）
        │
        ▼
人工确认（差异预览）→ POST /api/workflows/runs/{run_id}/steps/{n}/review
  │  approve → 运行继续   skip → 记跳过继续
  │  abort  → 运行中止（已确认步骤输出保留，可回看）
```

### 3.3 模块划分

| 层 | 新增内容 | 说明 |
|---|---|---|
| 数据层 | `workflows` / `workflow_steps` / `workflow_runs` / `workflow_run_steps` 四表（见 §4），db.py `MIGRATIONS` 增量迁移 + 内置示例种子 | 沿用裸 sqlite3，零 ORM |
| 后端 API | `app/api/workflows.py` 新路由，`app/workflow_engine.py` 运行器 | 引擎只依赖 `features.build_skill_system_prompt` 与 `ai_client.chat/chat_stream` 两个既有入口 |
| 任务台账 | 步骤执行照常 `create_task(...)`，运行级不重复建表，进度聚合自 `workflow_run_steps` | 与任务中心范式一致 |
| 前端 | `static/js/pages/workflows.js` 新页面 + 侧栏导航项「写作工作流」 | 列表 / 编辑器 / 运行视图三态，同页切换 |
| 测试 | `tests/test_workflows.py`（API + 引擎，AI 用 `scripts/mock_ai.py` 打桩） | 纳入 pytest 与 CI 回归 |

## 4. 数据模型（db.py 增量迁移）

```sql
-- 工作流定义
CREATE TABLE IF NOT EXISTS workflows (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT NOT NULL,                -- 展示名
    description TEXT NOT NULL DEFAULT '',
    icon        TEXT DEFAULT 'account_tree',
    scope       TEXT DEFAULT 'global',        -- global | work:<work_id>
    enabled     INTEGER DEFAULT 1,
    builtin     INTEGER DEFAULT 0,            -- 内置示例禁删，可复制
    created_at  TEXT DEFAULT (datetime('now','localtime')),
    updated_at  TEXT DEFAULT (datetime('now','localtime'))
);

-- 步骤定义（有序）
CREATE TABLE IF NOT EXISTS workflow_steps (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    workflow_id   INTEGER NOT NULL REFERENCES workflows(id) ON DELETE CASCADE,
    seq           INTEGER NOT NULL,           -- 执行顺序，从 0 起
    title         TEXT NOT NULL,              -- 展示名，如「生成本章草稿」
    skill_id      INTEGER REFERENCES skills(id),   -- 核心：绑定的 Skill
    input_mode    TEXT DEFAULT 'chapter',     -- chapter | prev_output | merge | none
    prev_step_seq INTEGER,                    -- input_mode=prev_output 时引用步骤 seq
    output_var    TEXT DEFAULT '',            -- 输出变量名（供 {{steps.N.output}} 或后续引用）
    instruction   TEXT DEFAULT '',            -- 固定补充指令（注入 {{instruction}}）
    length        TEXT DEFAULT 'medium',
    candidates    INTEGER DEFAULT 1,
    requires_review INTEGER DEFAULT 1,        -- 人工确认闸
    enabled       INTEGER DEFAULT 1,
    created_at    TEXT DEFAULT (datetime('now','localtime')),
    updated_at    TEXT DEFAULT (datetime('now','localtime'))
);

-- 运行实例
CREATE TABLE IF NOT EXISTS workflow_runs (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    workflow_id  INTEGER NOT NULL REFERENCES workflows(id),
    work_id      INTEGER REFERENCES works(id),
    chapter_id   INTEGER,
    status       TEXT DEFAULT 'pending',      -- pending|running|awaiting_review|done|failed|cancelled
    current_step INTEGER DEFAULT 0,
    error_msg    TEXT DEFAULT '',
    token_used   INTEGER DEFAULT 0,
    started_at   TEXT,
    finished_at  TEXT,
    created_at   TEXT DEFAULT (datetime('now','localtime'))
);

-- 运行步骤状态与产出
CREATE TABLE IF NOT EXISTS workflow_run_steps (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    run_id       INTEGER NOT NULL REFERENCES workflow_runs(id) ON DELETE CASCADE,
    step_seq     INTEGER NOT NULL,
    title        TEXT NOT NULL,
    ai_task_id   INTEGER,                     -- 关联 ai_tasks 台账
    status       TEXT DEFAULT 'pending',      -- pending|running|awaiting_review|approved|skipped|failed
    output       TEXT DEFAULT '',
    review_note  TEXT DEFAULT '',
    token_used   INTEGER DEFAULT 0,
    elapsed_ms   INTEGER DEFAULT 0,
    updated_at   TEXT DEFAULT (datetime('now','localtime')),
    UNIQUE(run_id, step_seq)
);
```

要点：
- 运行状态全部落库 → 关窗、重启 exe 后打开运行视图即可恢复到中断点（R8/R11）
- 步骤输出上限与 Skill references 同量级（单步输出截断至 32K 字符入库）

## 5. API 设计（`app/api/workflows.py`，prefix `/workflows`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/workflows` | 列表（可按 scope / enabled 过滤） |
| POST | `/workflows` | 创建工作流（含初始步骤数组） |
| GET | `/workflows/{id}` | 详情 + 步骤列表（含 Skill 标题快照） |
| PATCH | `/workflows/{id}` | 更新元数据 / 启停 |
| DELETE | `/workflows/{id}` | 删除（builtin 禁删，返回 403） |
| POST | `/workflows/{id}/duplicate` | 复制（含步骤） |
| PUT | `/workflows/{id}/steps` | 全量替换步骤数组（编辑器保存，后端重排 seq） |
| POST | `/workflows/{id}/runs` | 启动运行 `{work_id, chapter_id}` → `{run_id}`；服务端后台 asyncio 任务执行 |
| GET | `/workflows/runs/{run_id}` | 运行详情 + 全部步骤状态与输出（运行视图轮询，1s） |
| POST | `/workflows/runs/{run_id}/steps/{seq}/review` | `{action: approve\|skip\|edit, content?, note?}` — edit 时用人工修改稿作为该步输出 |
| POST | `/workflows/runs/{run_id}/cancel` | 中止 |
| POST | `/workflows/runs/{run_id}/retry` | 从失败/中止步骤重跑 |
| GET | `/workflows/runs` | 运行历史列表 |

运行器接口约定：`workflow_engine.py` 暴露 `start_run(run_id) -> asyncio.Task`、`resume_run(run_id)`、`cancel_run(run_id)`；引擎内部每步调用 `features.build_skill_system_prompt` + `ai_client.chat`（非流式先行的 P0，流式在运行视图用「已完成步骤全文 + 进行中文本逐字出现」模拟打字机，后续版本接真流式）。

## 6. 前端设计（`static/js/pages/workflows.js`）

**三态同页**（沿用墨语页面范式：`ui.el` 构建 DOM、Tailwind 工具类、无构建步骤）：

1. **列表态**：工作流卡片（图标、名称、步骤数、运行中徽标、启停开关）+ 「新建 / 复制 / 删除」；顶部大标题沿用 `font-display text-display` 页头范式。
2. **编辑态**：左侧步骤纵向列表（拖拽排序用 HTML5 DnD，与章节排序同模式），右侧步骤参数表单：
   - 绑定 Skill：下拉（来源 `GET /skills?enabled=1`，显示 title + applies_to 徽标）
   - 输入来源：`本章正文 / 指定前序步骤输出 / 合并（正文+前序输出）/ 无`
   - 输出变量名（默认 `step{N}`）、长度档位、候选数、固定指令 textarea
   - 「完成后需我确认」开关（默认开，醒目的朱砂色强调——这是安全红线）
3. **运行态**：顶部进度条（当前步/总步）+ 步骤竖向时间线；每步卡片显示状态徽标（等待/运行中/**待确认**/完成/跳过/失败）、输出全文、token/耗时；**待确认步骤**高亮展开，操作区四键：采纳继续 / 编辑后继续（内联 textarea，预填输出）/ 跳过 / 中止运行。

导航：侧栏新增「写作工作流」（图标 `account_tree` 或 `route`），置于「Skill 市场」之后。

## 7. 安全与降级

- **确认闸强制**：引擎推进逻辑以 `workflow_run_steps.status` 为准；`requires_review=1` 的步骤只有收到 `approve`/`edit`/`skip` 才置后续步骤 `pending→running`。后端校验，不信前端传参。
- **零静默写正文**：本功能所有输出只落在 `workflow_run_steps.output` 与预览区；写回正文只能走 R10 的「写入草稿区」（工作台暂存，不覆盖已有正文，且触发版本快照）。
- **Skill 失效降级**：步骤绑定的 Skill 被删除/禁用时，运行该步前校验并给出明确错误（复用 `resolve_skill` 的 400 语义），支持换绑后重试。
- **AI 未配置**：启动运行前统一检查 `get_ai_config()`，未配置直接 400 并 toast 引导设置页（与现有行为一致）。
- **运行隔离**：并发运行同一工作流允许，但 `workflow_runs` 独立成实例互不干扰；取消即置 `cancelled`，后台任务在下个步骤边界退出。

## 10. 非目标与风险

**本期不做**：循环/条件分支（R13）、工作流市场分享（R12 仅留导出）、步骤级真流式 SSE（P1 后评估）、自动写正文（任何版本都不做，写回永远经草稿区+快照）。

**风险与对策**：
1. **长链路上下文膨胀** —— 多步输出链式引用可能超模型窗口；对策：input_mode=merge 时截断前序输出（保留头尾各 2K 字），引擎记录截断标记。
2. **确认闸体验割裂** —— 每步都停会打断心流；对策：示例工作流只给「生成草稿」开确认，检查/润色步骤默认自动通过（用户可自行改）。
3. **并发运行与 SQLite 写锁** —— 引擎写步骤状态集中在步骤边界，单写者模式，避免长事务。
