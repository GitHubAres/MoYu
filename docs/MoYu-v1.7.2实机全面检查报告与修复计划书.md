## 三、 检查发现的问题与根本原因定位 (Defects & Root Causes)

虽然前端页面渲染与常规功能测试全部通过，但通过对全工作区静态与动态深潜排查，发现了以下 **4 个问题**（包含 1 项重大隐性乱码缺陷）：

### 🔴 问题 1（重大隐患）：后端 AI 报错与模型拉取文案中残留 26 处 `????` 乱码
- **受损文件**：
  1. `app/ai_client.py`（24 处 `????`）：
     - 第 172 行：`"message": "API Key ???????401?"`
     - 第 182 行：`"message": "?????????????"`
     - 第 192 行：`"message": f"AI ???????{resp.status_code}??{resp.text[:200]}"`
     - 第 247 行：`msg = "????????? 500 ???"`
     - 另外包括该模块内部大量函数注释和 docstring 中的中文被损毁。
  2. `app/features.py`（2 处 `????`）：
     - 第 346 行：`"message": "????AI ??????? Base URL ? API Key"`
- **根本原因**：
  在 v1.7.0 迭代引入“AI 模型自动拉取与缓存”功能时，后端 Python 代码在 Windows GBK 环境下被读写保存，导致中文字符编码受损，退化为 ASCII 63（`?`）。由于此前测试大多覆盖成功路径（Happy Path）或通过 Mock 绕过了真实报错返回，导致该隐蔽问题未在前端测试中暴露。
- **潜在危害**：
  一旦用户在设置页填写了错误的 API Key（触发 401）、访问了不兼容 `/models` 的服务商（触发 404）、遭遇服务商服务器故障（500）或未填配置点击测试时，后端返回的 JSON 数据中携带 `????`，前端弹出 Toast 时会再次将问号乱码呈现给用户！

---

### 🟡 问题 2（中等）：测试文件 `tests/test_ai_models.py` 文档注释被污染
- **受损文件**：`tests/test_ai_models.py`（共 39 处 `????`）
- **根本原因**：与问题 1 同批次引入，测试用例文档字符串（docstrings）、分步测试说明及断言注释出现大面积乱码，降低了代码可读性与后续协同维护效率。

---

### 🟡 问题 3（体验优化）：Skill 标识名（`name`）命名正则严格限制，缺少前端友好前置校验
- **表现**：
  - 后端对 Skill `name` 字段使用强正则校验：`re.compile(r"^[a-z0-9][a-z0-9-]{0,63}$")`；
  - 命名仅允许小写字母、数字和中划线（`-`），**严格禁止下划线（`_`）**与大写字母；
  - 若用户在输入自定义 Skill 标识时输入 `combat_polish`，后端会直接返回 400 Bad Request；
  - 前端 Skill 表单未在用户输入时进行实时格式防呆校验，提示文案不够直观。

---

### 🟢 问题 4（接口规范）：缺少通用的 `/api/version` 路由
- **表现**：
  当前版本信息被挂载在 `/api/health` 中（`{"app": "moyu-local", "version": "1.7.2"}`）；外部集成或用户排查时习惯性调用 `/api/version` 会返回 404 Not Found。建议增加直接别名映射。
