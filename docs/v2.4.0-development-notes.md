## 一、本次迭代目标与核心交付

### Phase 1：SSE 正文流式打字机与中断机制 (已完成)
- **后端**：
  - 新增 `POST /api/ai/generate/stream` 接口，基于 Server-Sent Events (SSE) 协议提供毫秒级逐字打字机推送。
  - 支持客户端主动中断（Disconnect / Cancel 请求），通过连接断开捕获与标记，安全终止大模型上游请求，并在正文尾部安全追加 `[已中止]` 标记，避免内容乱入或丢失。
- **前端工作台**：
  - 正文写作区集成流式输出，打字机实时上屏。
  - 沉浸写作栏增加红白双色「停止生成」悬浮控制按钮，点击即刻打断生成并沉淀已生成文字。

### Phase 2：长文工作流步骤级实时输出与断点续跑 (已完成)
- **后端**：
  - 工作流运行器引入全局内存流式输出缓冲区 `_live_buffers` 与 `GET /workflows/runs/{run_id}/live-output` 实时轮询接口。
  - 增加单步断点重试接口 `POST /workflows/runs/{run_id}/steps/{seq}/retry`，支持对失败或待人工审核的步骤进行原位回滚并从当前步骤继续执行。
- **前端工作台**：
  - 工作流运行页面增加「实时推演输出」动态流式展示面板，展示当前步骤生成中的正文。
  - 步骤卡片支持「重新执行本步 (断点续跑)」功能，大幅提升长篇策划体验。

### Phase 3：工作流步骤产物一键反哺正文与设定集 (已完成)
- **目标**：彻底打通工作流策划推演成果向「作品库基础信息、万相谱实体、大纲与梗概、时间线、伏笔、术语世界观、目标章节正文及版本历史」的一键式闭环同步。
- **后端**：

  - 自动触发 `word_count` 实时重新统计正文字数，并在 `chapter_versions` 版本快照库中记录带有工作流运行与步骤标记的版本记录，保证正文可撤销、可追溯、防覆盖。

- **后端**：

  - 在 `sync_assets_to_database` 中：当选择 `append` 追加模式且章节已有正文时，自动在章节末尾保留空行追加新剧情正文，重新计算全文字数，并在版本历史中明确标记为「工作流 #X 步骤 Y 追加」。
- **前端工作台**：
  - 资产同步弹窗的正文卡片内增加了模式切换：**「全量覆盖」** 与 **「追加到文末」** 单选控制。

## 三、小说作者实机体验与问题总结

站在网文作者在 VPS 实机创作的角度，对墨语各模块及新增功能进行全链路体验评估：

1. **正向体验与亮点**：
   - **流式打字机响应迅捷**：在 VPS 网络延迟环境下，写作工作台的 SSE 流式打字机体验顺畅，极大地缓解了以往等待大模型完整返回时的“白屏焦虑”；随时可中断的设计对长文构思非常友好。
   - **步骤级推演与断点续跑**：长文工作流执行耗时较长，现在能实时看到当前步骤推理产生的文字，遇到满意的步骤可直接同步，遇到偏离的步骤单步重试，无需从头重跑整个工作流。
   - **一键反哺闭环完整**：工作流推演出来的世界观设定、人物角色卡、大纲伏笔和生成的剧情正文，可以在一个弹窗内一次性审核、按需勾选并分别导入到对应模块，且正文写入带有版本保护，消除了改稿后找不回原稿的后顾之忧。

2. **作者视角的后续优化建议**：
   - **正文反哺差异对比 (Diff View)**：当前如果目标章节内已有较多正文，作者在将工作流生成的内容反哺入库时，建议未来提供并排对比或追加（Append）/ 替换（Replace）模式选择，避免作者手动去合并前后的文字。
   - **移动端工作流卡片折叠**：在窄屏或手机端，工作流步骤卡片内容较多时垂直滚动距离偏长，后续可增加默认折叠已完成步骤、仅展开当前正在执行步骤的自适应模式。
