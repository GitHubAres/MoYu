## 1. 核心需求与交付内容

依据 `docs/moyu-chat-upgrade-plan.md`，在**严格保证内容安全红线（AI 内容必须先预览经确认才写入正文）、桌面三栏体验 100% 零回归、原生纯 JS 无构建链路**的前提下，完成「AI 修撰使」由单轮任务模式向多轮对话式伴写窗口的全面升级：

### 1.1 数据持久层扩展（`app/db.py`）
- 在 SQLite `SCHEMA` 中新增两张会话与消息审计表：
  - `chat_sessions`：按作品及章节关联独立存储多轮会话（`id`, `work_id`, `chapter_id`, `created_at`, `updated_at`），建立章节索引 `idx_chat_sessions_chap`；
  - `chat_messages`：记录具体交互流（`id`, `session_id`, `role`, `content`, `task_type`, `meta_json`, `adopted`, `created_at`），建立会话正序索引 `idx_chat_messages_session`；
- 继承裸 SQLite3 增量升级机制，保证已有数据库开箱自动初始化新表，零数据破坏。

### 1.2 服务端 API 与多轮编排（`app/api/chat.py`）
- 新增独立路由模块并在 `app/api/__init__.py` 注册：
  - `GET /api/chat?chapter_id={id}`：按章节隔离加载当前激活会话与全部时间正序消息；
  - `POST /api/chat`：支持流式与非流式调用，自动 `get_or_create` 会话；读取当前会话全部历史消息映射为 `user` / `assistant` 数组，将当前章节上下文、选区引用与写作要求拼装入本轮最后一条消息；流式输出完成时原子落库；
  - `POST /api/chat/session/new`：支持用户显式开启新会话，重置上下文计数；
  - `PATCH /api/chat/messages/{message_id}`：支持消息采纳（`adopted=1`）与撤销采纳（`adopted=0`）状态回写；
- 保持既有 `/api/ai/generate` 接口 100% 不动，向前兼容经典生成逻辑。

### 1.3 前端多轮对话聊天面板（`static/js/pages/workbench_chat.js`）
- 采用 **Literary Minimalist Ink（黛青 #1B2A38 + 朱砂 #D9483B）** 文人书斋设计规范：
  - **头部导航区**：修撰使头像标识 + 标题 + ⚙精调抽屉开关 + 「新对话」按钮；
  - **精调抽屉**：默认折叠，提供长度/候选/提示词模板精调，以及**「经典多候选对比模式」一键切换开关**；
  - **上下文折叠栏**：显示“已挂载 N 项上下文”，点击优雅展开章节前文、大纲与设定实体明细；
  - **气泡消息流**：用户气泡右对齐（朱砂暖色调）、AI 气泡左对齐（黛青底色与任务徽标），支持纯文本安全渲染与 SSE 流式打字机；
  - **气泡操作栏**：包含「采纳」、「复制」、「重试」、「放弃」；采纳后原地切换为「已采纳 / 撤销采纳」；
  - **固定输入区**：底部固定，提供 `[续写 | 扩写 | 缩写 | 改写]` 快捷标签，支持选区引用条提示（“已引用选区 N 字 ×”），Enter 发送 / Shift+Enter 换行。

### 1.4 工作台集成与无缝降级（`static/js/pages/workbench.js`）
- `buildAiPanel()` 深度接入 `window.WorkbenchChat`；
- 保持编辑器选区浮动工具栏（Floating Toolbar）无缝联动，点击快捷标签可直接唤起聊天发送；
- 章节切换时自动调用 `loadChapter()` 恢复对应章节专属对话流；
- 正文采纳时严格执行“快照备份 → 替换/追加 → 写入正文 → 提供撤销”的安全保护链路。

## 3. 改动边界与已知问题

1. **改动边界**：
   - 本次改动仅聚焦于写作工作台右栏 AI 辅助面板，未修改任何已有作品正文、大纲或设定实体；
   - 保持了旧版多候选对比（classic mode）的代码与 UI 入口，保证老用户使用习惯不被强制剥夺。
2. **已知问题与环境提示**：
   - 多轮对话历史目前默认装配当前 session 的全量消息，未来若对话轮次超过 20 轮，建议引入历史滑动窗口或记忆摘要剪枝。
