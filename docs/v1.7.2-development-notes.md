## 1. 核心修复背景与根本原因

在 v1.7.0 / v1.7.1 迭代中，用户反馈“系统设置 → AI 模型配置”中的模型列表快速选择器界面出现大量“?”问号乱码占位符（例如：`??`、`????` 等文本标签）。

### 根本原因分析
1. **Windows 默认代码页与文本读写转码损毁**：
   在 Windows 宿主环境下，某些外部脚本或操作以默认 GBK/CP936 代码页读写无 BOM 的 UTF-8 前端源文件，将中文字符转码受损，生成了不可逆的 ASCII 63（`?`）占位符。
2. **缺乏静态资源编码回归测试**：
   原有测试集覆盖后端 API 及桌面生命周期，缺乏对 `static/` 目录下 JS/HTML 文件关键编码完整性与乱码占位符的自动化断言。

---

## 2. 解决方案与防范机制

1. **全面净化重构并恢复标准 UTF-8 编码**：
   - 彻底修复 `static/js/pages/settings.js` 中 `createModelPicker` 交互组件与 `ui.js` 注释。
   - 所有中文字符恢复为规范的 Unicode/UTF-8 字符（包含各厂商模型分组标签、常用模型提示、搜索占位符、Toast 提示及自定义输入指引）。
   - 确保文件以纯净 UTF-8（无 BOM）保存，杜绝乱码残留。
2. **新增静态资源编码长效测试 (`tests/test_frontend_encoding.py`)**：
   - 自动化扫描前端核心 JS/HTML 资源，严格断言禁止出现连缀乱码问号（`？？`），纳入常规 pytest 与 CI 回归套件。
   - 永久防范未来多协作方或不同终端编辑导致编码破坏。
3. **版本升级与验证**：
   - `app/version.py` 升级至 `1.7.2`。
   - 自动化回归测试用例总数达 **103 项**（100% Pass）。
   - 触发 CI 自动化构建 Windows 原生客户端并同步至 VPS 生产环境。
