## 一、问题详情

### 全站通病

#### 全1. AI 功能调用缺乏交付记录与运行状态反馈【部分属实】

- **验证**：运行动画**已存在**——`loadingCard` 组件含旋转 spinner 与提示文案（`static/js/pages/alchemy.js:133-137`）；但**交付记录确属缺失**——数据库无 AI 任务表（`db.py` SCHEMA 无 `ai_tasks`/`deliveries`），AI 调用结果不落库，页面切换即丢（SPA 路由切换重建 DOM，任务状态仅存于页面闭包）。
- **专业重述**：AI 任务系统缺少持久化的任务台账（Task Ledger）机制，任务生命周期为"单次同步 HTTP 请求 + 前端内存态"，无任务编排、无断点续跑、无统一 token 记账。
- **开发方向**：见"三、跨问题归纳 A"——建立统一 AI 任务基础设施（任务表：类型/输入摘要/状态/输出/耗时/token 消耗），所有 AI 入口写台账，列表页可回溯、可重试。此项与 后续 AI 编排能力合并实施。

### 书架作品

#### 书1. 书籍分类属性无修改入口【属实】

- **验证**：数据层与 API 层均已就绪——`works.genre` 字段（`db.py`）、`PATCH /works/{id}` 白名单含 `genre`（`app/api/works.py:88`）；但前端**无任何编辑入口**：书籍卡片仅提供"继续写作/重命名/删除"（`static/js/pages/bookshelf.js` workCard），卡片上显示的"未分类"只读。
- **专业重述**：作品元数据（genre/intro/status/cover_color）后端可写、前端无编辑 UI，属功能覆盖缺口（UI Coverage Gap）。
- **开发方向**：P0。书籍卡片增加"编辑"入口，弹出作品属性对话框：分类（下拉：玄幻/仙侠/都市/科幻/历史/言情/悬疑/其他，可扩展）、简介、连载状态、封面底色。复用现有 PATCH 接口，纯前端工作量。

#### 书2. 灵感便签无删除功能；建议悬浮快捷记录【误报 + 合理建议】

- **验证**：**删除功能存在**——后端 `DELETE /notes/{id}`（`app/api/notes.py:46`）；前端每条便签 hover 显示编辑/删除按钮（`bookshelf.js` notesPanel）。**问题真实存在但被误诊**：操作按钮采用 `opacity-0 group-hover:opacity-100`，触屏设备与未触发 hover 的用户**不可见**，属可发现性（Discoverability）缺陷而非功能缺失。"悬浮按钮快捷记录"建议**合理**——当前便签入口仅书架页侧栏，缺乏全局快捷入口。
- **开发方向**：P0。① 便签操作按钮改为常显（或主操作常显、次操作 hover）；② 增加全局悬浮记录按钮（FAB）+ 快捷键（如 `Ctrl+J`），任意页面唤起快速记录弹层——与既有 `Ctrl+K` 全局搜索交互范式一致。

#### 书3. "书架作品"升级为 Dashboard 看板【属实 · 增强方向】

- **验证**：方向与产品自我定位一致——书架页页眉已标注 `CREATOR DASHBOARD · 本地`（bookshelf.js），后端统计接口 `/stats/dashboard`（总字数/今日字数/作品数/章节数）已实现（`works.py` 末尾）；但前端未组装为看板，"书架"仍是平铺卡片列表。
- **开发方向**：P2。书架页改版为看板布局：顶部统计条（今日字数/连续写作天数/总字数——统计 API 已具备）+ 书架作品作为其中一个模块 + 灵感便签模块 + 最近编辑/待回收伏笔等模块预留位。产品规划中"字数统计（全书/当日/连续天数）"已承诺，此前端化即可兑现。

#### 书4. 书籍编辑元素过少；封面自定义上传；接入丹青阁产物库【部分属实】

- **验证**：① "可编辑元素少"**属实**（同书1，编辑入口整体缺失）；② `cover_image` 字段已存在（`db.py` MIGRATIONS）且卡片显示逻辑已支持图片封面（优先于纯色块，`bookshelf.js` workCard），但 `PATCH /works` 白名单不含 `cover_image`、且无上传 UI——**封面自定义上传属实缺失**；③ 丹青阁**已存在**（`app/api/gallery.py`，AI 生成封面/插图 + 图库管理 + 一键设封面，产品规划第 4 节），用户设想的"AI 产物库"方向正确且已有雏形；封面从丹青阁图库选取可行，缺打通。
- **开发方向**：P1。① PATCH 白名单补充 `cover_image`；② 编辑对话框内封面子模块：本地上传 / 从丹青阁图库选择 / 纯色+首字回退；③ 中期将丹青阁演进为统一"AI 产物库"（封面、插图、未来扩展产物统一归档检索），书籍封面作为其消费方之一。

### 写作工作台 · 章节

#### 章1. 章节标题命名不统一（"第一章"与"第2章"混用）【属实 · 根因定位】

- **验证**：**双端默认生成逻辑不一致**——书架"新建作品"默认建章 `title="第一章"`（中文数字，`bookshelf.js` createWorkDialog）；工作台"新建章节"默认 `title=第${vol.chapters.length+1}章`（阿拉伯数字，`workbench.js` newChapter）。`chapters` 表无章节号字段，标题为自由文本，故同书内必然混用。
- **专业重述**：缺少章节编号规范化层（Chapter Numbering Normalization），标题生成逻辑分散于多入口且无统一规则。
- **开发方向**：P0。① 统一两端默认生成器（建议中文数字"第一章"，与品牌书卷气质一致）；② 新建章节自动取"当前卷内最大序号+1"，避免删除章节后重号；③ 长期：标题与序号解耦（`chapter_no` 字段 + 显示模板），支持"第X章/Chapter X/自定义前缀"设置，重排序自动重编号——此项依赖数据结构变更，建议并入 v1.2 版本计划。

#### 章2. 章节信息与故事大纲不同步；卷/章表达逻辑不一致【属实】

- **验证**：系统存在两套并行结构——**卷-章树**（`volumes`/`chapters`，组织实体）与**大纲节点树**（`outline_nodes` + `chapter_id` 软映射，`SET NULL`）。两端问题：① 章节重命名不回写已映射的大纲节点（`outline_nodes.title` 独立存储，无同步钩子）；② 大纲侧"生成章节草稿"创建真实章节后，两套结构靠人工对齐；③ 大纲节点可跨"卷"自由分层，与工作台"卷→章"二级固定层级心智模型不同——用户感知的"逻辑不一样"源于**组织模型双轨**（自由树 vs 固定层级）。
- **开发方向**：P1。短期：章节重命名/删除时同步维护映射节点标题与提示（后端钩子）；中期（v1.2）：定义单一事实来源——章节实体为唯一正文载体，大纲节点为纯叙事结构视图，映射关系双向显式展示（工作台章节点标注"已映射大纲节点"，大纲节点侧标注所属卷章），消除双轨漂移。

### 写作工作台 · AI

#### AI1. "任务"交互逻辑需为 Skill 扩展预留【属实 · 架构需求】

- **验证**：提示词中心页面与 prompts 数据表已存在，当前任务选择器仍是固定分段控件，前端尚未接通自定义模板选择。
- **专业重述**：任务选择器需从静态枚举演进为动态 Skill 注册表（Skill Registry），支持内置任务 + 用户自定义提示词模板以"技能"形式挂载进工作台。
- **开发方向**：P1。任务区改为动态加载（内置四任务 + 自定义 skill 列表），选中 skill 即加载其模板与参数说明；与提示词中心共享 `prompts` 数据源。此改造与 v1.2 编排引擎合并设计，避免二次返工。

#### AI2. AI 面板聚合关联功能与跳转入口【属实 · 交互增强】

- **验证**：工作台 AI 面板仅有"生成"单功能；一致性检查（`audit.py`，AI 稽核附原文引用）、大纲剧构推演（`outline.js`）、炼丹生成（`alchemy.js`）等 AI 能力入口分散于各页，工作台上无快捷跳转。
- **开发方向**：P2。AI 面板增加"相关能力"区：一致性检查（当前章）、去 AI 味改写（v1.3 规划）、跳转链接至炼丹炉/提示词中心——与 AI3 合并设计。

#### AI3. "墨语MoYu 修撰使"人设与能力需丰富【属实 · 增强】

- **验证**：当前修撰使 = 无状态单轮生成器（任务/长度/候选 + 自由指令，结果走差异预览确认链路）；上下文挂载仅"当前章节 + 前章末尾 500 字 + 关联设定"，且代码留有"关联设定暂无数据来源"TODO（注：该 TODO 已过时——`/chapters/{id}/entities` 接口已存在，接入即可）；无多轮对话记忆、无人格化系统提示。
- **开发方向**：P2。① 修撰使人格化系统提示（契合"修撰使"中式文人助手设定，区别于通用 AI 口吻）；② 多轮会话记忆（会话表 + 上下文窗口管理）；③ 上下文挂载扩展：大纲节点、伏笔条目、时间线事件、自定义设定勾选；④ 与 AI2 合并为"修撰使工作台"改版。

### 故事大纲

#### 纲1. "新建大纲节点"内嵌 AI 生成，免切换页面【属实 · 增强】

- **验证**：大纲新建节点为纯手填（`outline.js` createNode）；炼丹炉"开炉炼丹"四步管线含故事大纲生成（框架→世界观→人物→大纲），两功能割裂，需跨页操作。
- **开发方向**：P2。大纲节点创建弹层增加"AI 生成"页签（调用既有开炉大纲生成能力，以当前节点/选中节点为锚点生成子节点预览，走确认链路入库）——注意保持 AI 安全模型：生成内容预览确认后才创建节点。

### 炼丹炉 · 资料融汇

#### 丹1. 脱离前台运行报错【属实 · 任务生命周期缺陷】

- **验证**：资料融汇为前端 `await` 单次请求（`alchemy.js` fuse 流程），AI 调用超时阈值 120s（`ai_client.py:11`）；任务状态纯内存，路由切换/页面刷新即中断丢弃。"报错"来源：超时触发 `httpx.TimeoutException`，或服务端 502 包装后前端 toast。用户感知的"脱离前台"（切页/失焦后再回来结果丢失并报错）**属实**。
- **专业重述**：长时 AI 任务缺乏异步任务化（Async Taskization）——无任务队列、无后台执行、无状态恢复。
- **开发方向**：P1，与全1/丹3 合并：任务提交后立即返回 task_id，后台执行；前端轮询/订阅任务状态；任务结果落库，切页回来可查看/续用，中断可重试——避免重复调用浪费 token。

#### 丹2. 智能分类等候无交互动画【误报】

- **验证**：**动画存在**——点击后右栏替换为 `loadingCard`（旋转 spinner `progress_activity` + "AI 思考中"文案）。用户未感知的可能原因：长等待中动画静止感强、无步骤进度、无预计时长、无取消按钮。
- **开发方向**：P3（优化项）。任务基建落地后，等候 UI 升级：步骤化进度（解析→分类→生成预览）、预计时长提示、取消按钮、完成通知（离开页面后回来自动弹出结果）。

#### 丹3. 缺交付记录，中断后需重跑浪费 token【属实】

- **验证**：与全1同根因；且资料融汇的中间结果（AI 分类输出）不落库，中断=全量重跑，token 成本翻倍。
- **开发方向**：P1，随任务基建一并解决：AI 原始输出与最终入库产物均写入交付记录，支持"从中断点续跑"与"结果复用"。

#### 丹4. 智能分类后导入未包含作品内容【设计预期】

- **验证**：资料融汇的设计语义为**设定知识抽取**——`/alchemy/import-lore` 仅接收实体 + 大纲节点两类结构化产物（`alchemy.js:456`），不导入正文章节；正文导入属"导入导出"模块（智能拆章，io 页面）职责。**非缺陷**，但功能边界用户不可知，UI 未澄清。
- **专业重述**：功能定位认知偏差——"资料融汇"（参考材料→设定库）与"作品导入"（正文→章节树）是两条独立管线，UI 文案未做心智分隔。
- **开发方向**：P2。① 资料融汇结果页明确标注"本功能仅抽取设定与大纲，不含正文导入"，附跳转"导入作品"链接；② 评估增加"同时导入正文为草稿章节"可选能力（技术上可复用拆章管线），作为 v1.3 候选需求。

## 三、跨问题归纳（架构层共性根因）

### A. AI 任务系统缺统一基础设施（关联：全1 / 丹1 / 丹3）

三项反馈指向同一根因：**无任务持久化层**。建议建设统一 AI 任务基础设施（对应 后续 AI 编排能力的底座）：

- 任务表：`task_type / 输入摘要 / 状态(pending|running|done|failed|cancelled) / 输出引用 / token 消耗 / 耗时 / 错误信息 / 关联作品`
- 全部 AI 入口（续写/审计/资料融汇/炼丹/生图）统一走任务层：提交→后台执行→前端订阅状态→结果落库
- 交付记录列表页（按作品/类型/时间过滤），支持重试与结果复用
- 该基建同时是 InkOS 对比规划中"交付记录"和 v1.2"编排引擎"的落地抓手，**建议在 v1.2 优先实施**

### B. 前端编辑入口覆盖率低（关联：书1 / 书4）

后端 PATCH 白名单早已支持作品元数据编辑，前端缺编辑 UI。属"API-UI 覆盖剪刀差"，P0 纯前端补齐。

### C. 命名与同步规范化缺失（关联：章1 / 章2）

章节编号无统一生成器、章节↔大纲双轨无同步钩子。短期前端统一规则，中期数据结构解耦（`chapter_no` + 映射同步钩子）。
