## 一、本次迭代目标与里程碑

墨语 MoYu 正式发布 **v2.1.2** 版本。本版本彻底解决了从 sepia 写作工具移植至墨语过程中的**内置预设 Skill 本地化残留问题**，固化了技能占位符契约，消除了规则冲突，并完善了文档与部署体系：

1. **路由与校准体系统一（T 组已合入）**：
   - 润色改写技能（`default-rewrite`）深度接入 sepia v2 校准体系与痕迹词表（T-1）。
   - 修正 `TASK_SKILL_MAP` 中 `check` 任务路由，使其精确映射至 `default-audit`（设定检查，T-2）。
   - 新增针对路由与手册绑定的单元测试，全量测试用例基线提升至 207。

2. **幽灵技能名彻底清除（阶段 1）**：
   - 全面替换 7 个旧工具遗留的幽灵名称（`novel-outline` -> `default-outline`、`novel-condensation` -> `default-shorten`、`novel-continuation` -> `default-continue`、`novel-expansion` -> `default-expand`、`novel-rewriting` -> `default-rewrite`、`novel-consistency-check` -> `default-audit`、`novel-analysis` -> `default-analysis`）。
   - `app/` 源码实现零幽灵名残留。

3. **英文触发词清理（阶段 2）**：
   - 彻底移除内置技能正文中遗留的 9 处英文触发词块，确保中文创作体验纯净统一。

4. **占位符契约守卫（阶段 3）**：
   - 固化技能输入占位符契约仅允许 `{{context}}`、`{{selection}}`、`{{instruction}}`。
   - 在 `app/db.py` 的技能 seed upsert 流程中增加非标准占位符扫描与警告守卫，防止自定义技能漏写占位符导致裸字符串透传。

5. **外部文件与环境假设改写（阶段 4）**：
   - 改写 `novel-forge` 与 `novel-world` 中关于“在项目目录新建 .md 文件”与 CLI Read 操作的陈旧表述，对齐墨语真实的作品备注、章节大纲与设定集资产链路。
   - 移除 `de-ai-tone` 中关于外部 Office 解析链路的无效说明，杜绝臆造 API。

6. **改写 12 字消痕规则与边界协调（阶段 5）**：
   - 修复 `default-rewrite` 中“连续12字雷同必须重写”与“未指定维度保持原样”之间的表述矛盾。
   - 明确规则：“改写以用户指定维度为边界；在该维度内连续12字以上与原文雷同且非关键台词/专名时必须重写消痕；未指定维度一律保持原样”，同时严格保留三占位符与 5 条准则。

7. **分场细纲与大纲防抢跑协同（阶段 6）**：
   - 在 `novel-scene` 排除段明确补充“章纲未定时先走 default-outline，不要抢做分场”，保障五连流工序严密递进。

8. **内置技能 Markdown 纯净度优化（阶段 7）**：
   - 移除内置技能 body_md 中冗余的 YAML frontmatter，正文以标准 Markdown 指令呈现，元数据由 Python 字典字段统一管理。
