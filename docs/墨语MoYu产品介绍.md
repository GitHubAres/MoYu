## 1. 一句话定位

**墨语MoYu** 是一款**部署在本地、数据不出机的 AI 长篇小说写作工作台**：从灵感整理、作品规划、正文创作、设定管理到作品导出的完整闭环，全部数据存于本地 SQLite，AI 只是可控的创作助手——所有 AI 生成内容先预览、由作者确认后才入库，绝不静默写入正文。

宣传语原句：**「一支笔、一炉丹、一盏灯——部署在本地、数据不出机的 AI 长篇创作工作台。」**

## 3. 目标用户与痛点

**核心用户**：网文作者、长篇小说创作者（单部长篇几十万到数百万字）。

| 痛点 | 墨语的对策 |
|---|---|
| 写到中后期设定崩坏、人物矛盾 | 万象谱设定库 + AI 一致性检查（附原文引用） |
| 伏笔埋了忘收 | 伏笔看板：埋设/待回收/已回收三栏闭环统计 |
| 剧情时间线混乱 | AI 从章节提取剧情事件，预览确认后入库 |
| 怕云端工具泄露未发表稿件 | 数据 100% 本地，无任何遥测上报 |
| AI 瞎写、污染正文 | 预览→采纳→可撤销→自动版本快照 |
| 灵感散落各处 | 书架灵感便签 + Ctrl+K 全局搜索 |
| 订阅费疲劳 | 本地软件形态，用户自配 API（用多少花多少） |

## 5. 技术与交付形态

- **交付形态**：Windows 单文件 exe（PyInstaller 打包，免安装、双击即用），自动启动本地服务并打开浏览器访问 `http://127.0.0.1:8321`；数据落在 exe 旁的 `data/` 文件夹，备份=复制文件夹，迁移=拷贝整个目录
- **技术栈**：Python 3.12 + FastAPI + SQLite（零 ORM）+ 原生 JS 单页应用 + Tailwind（全量本地化，断网可用）
- **AI 接入**：OpenAI 兼容协议文字接口，预设 DeepSeek / Kimi / 智谱 GLM / 通义千问 / OpenAI；生图走 SiliconFlow 等 OpenAI Images 兼容接口
- **隐私**：数据 100% 本地 SQLite；API Key 仅存本地库；无遥测、无上报
- **许可**：墨语 MoYu 按 MIT License 发布。
- **当前版本**：v1.1.0（本地版，采用 MIT License）。
- **开发效率卖点**：产品由 PRD + Stitch 设计稿驱动，约两天完成从设计到可分发 exe 的完整闭环

## 7. 命名与概念体系（品牌语言资产）

墨语把 AI 能力包装成一套**中式文人隐喻**体系，这是品牌表达的核心特色：

- **墨语**（产品名）→ 写作即落墨，作品即话语
- **书架 / 卷 / 章** → 传统书坊结构
- **万象谱** → 设定库（森罗万象，皆入谱中）
- **炼丹炉** → AI 创作生成（取材→炼化→成丹）
- **丹青阁** → AI 绘画（丹青=绘画，阁=收藏处）
- **伏笔看板 / 剧情时间线 / 关系图谱** → 功能直白命名，不用隐喻（避免过度装饰影响效率）
- **AI 安全模型**是产品价值观的集中体现：作者始终掌握最终裁决权

## 8. 对外传播注意（事实边界）

- 可以宣称：本地优先、MIT 开源、AI 可控、长篇创作管理。隐私描述应说明外部 AI 请求会发送用户选择的内容。
- 不要宣称：「完全离线也能用 AI」（AI 需用户自配在线 API）；「永不丢稿」（建议宣传自动快照+整库备份，但不做绝对承诺）；「适合所有人」（明确面向长篇/网文作者）
- 截图素材：`docs/screenshots/` 下有书架、工作台、关系图谱、炼丹炉四张官方截图
- 用户数据与 API Key 永不外泄、不入库——这也是产品价值观的一部分
