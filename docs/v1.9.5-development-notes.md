# 墨语 MoYu v1.9.5 开发说明与交付报告

**版本号：** v1.9.5  
**发布日期：** 2026-10-07  
**核心目标：** 重构写作工作流上下文装配契约，彻底解决“输入来源”与“引用哪一步输出”概念重叠、仅支持单步引用的弊端，实现多前序步骤产出自由多选、动态组合与三位一体大纲深度联动。

---

## 1. 架构重构与痛点解决

### 1.1 痛点诊断
1. **概念重叠与配置冗余**：过去步骤配置中，“输入来源”（chapter/prev_output/merge/none）与“引用哪一步输出”相互割裂，且在前端表现为两个生硬联动的下拉框；
2. **缺乏多前序步骤推演能力**：小说创作中，后续步骤（如分场细纲或剧情推演）往往需要同时参考前面多个步骤（例如同时参考“步骤1：故事立项” + “步骤2：世界观设定” + “步骤3：主要人物关系”），单整数 `prev_step_seq` 无法满足复合推演需要；
3. **缺少统一上下文装配契约**：模块间传递结构未显式规范，缺乏灵活组合章节正文、三位一体大纲卡与任意前序步骤产出的统一机制。

### 1.2 解决方案与新契约
1. **数据层与 Schema 增量迁移 (`app/db.py`)**：
   - 为 `workflow_steps` 增加 `ref_step_seqs TEXT DEFAULT '[]'`（存储引用的步骤序号 JSON 数组）和 `context_sources TEXT DEFAULT '["chapter","triad"]'`；
   - 保持与存量数据的 100% 双向平滑兼容（自动根据 `prev_step_seq` 和 `input_mode` 进行升降级兼容）。
2. **引擎上下文装配器 (`app/workflow_engine.py` & `app/services/context_service.py`)**：
   - 统一在 `_build_step_context` 中遍历 `ref_step_seqs`，按步骤时序格式化拼装多步产出：
     ```text
     【前序参考：步骤 1 (故事立项)】
     ...
     【前序参考：步骤 2 (主要人物)】
     ...
     ```
   - 每一段前序产出均有智能截断保护，支持指令模板变量 `{{steps.N.output}}` 全序列插值；
   - 结合 `context_sources` 动态装配目标大纲三位一体剧情卡与本章正文。
3. **前端步骤编辑与运行态界面重构 (`static/js/pages/workflows.js`)**：
   - 去除割裂的双下拉框，设计模块化「步骤上下文输入（动态装配）」卡片：
     - 基础源复选框：包含当前章节正文、包含大纲节点与三位一体剧情卡；
     - 前序步骤多选 Chips：直观勾选/取消勾选前面每一个步骤，提供“全选前序”与“清空前序”快捷操作；
   - 在运行界面中明确显示各步骤引用的前序链路提示标签（如“前序上下文参考：步骤 1、步骤 2”）。
