## 1. 核心需求与交付内容

依据后续规划路线，本版本重点实施了以下两大阶段的系统加固与创作力提升：

### 1.1 第一阶段：桌面网络弹性与全站按钮异常审计
- **底层通信弹性加固 (`static/js/api.js`)**：
  - 为 fetch 统一封装 45 秒超时机制（AbortController），杜绝无响应下的无限挂起；
  - 精细化错误类型提示：区分网络断开、服务端未就绪与超时，给予作者清晰友好的排查指引。
- **全局离线状态感知与灾备暂存 (`static/js/app.js`, `static/js/pages/workbench.js`)**：
  - 监听 window online/offline 事件并在页面即时通报；
  - 工作台引入浏览器离线容灾备份（`moyu_backup_ch_{chapter_id}`），按章节自动对输入进行实时本地暂存；
  - 打开章节时智能检查本地是否存在更新的未保存草稿，并提供一键恢复；
  - 注入 window beforeunload 防误关保护，页面存在未保存修改时主动拦截并保全。
- **全站异步操作防重与异常收敛**：
  - 针对书架示例作品生成、大纲状态流转、大纲梗概保存、设定库条目归档、伏笔泳道流转、版本手动快照、提示词复制、异步任务重试与取消等所有高频按钮，全面注入 `btn.disabled = true` 防重复触发锁；
  - 审计并消除空 catch 隐患，全面通过 ui.toast(..., "err") 暴露真实异常。

### 1.2 第二阶段：EPUB 电子书无依赖原生导出引擎
- **轻量原生 EPUB 引擎 (`app/exporter.py`)**：
  - 采用 Python 纯标准库 `zipfile` 实现，零额外第三方依赖；
  - 严格遵循 EPUB 3.0 / 2.0 规范：首部无压缩 `mimetype`、`META-INF/container.xml`、`OEBPS/content.opf`、`OEBPS/toc.ncx`、`OEBPS/style.css`、按卷和章节结构化的 XHTML 文件排版；
  - 支持全书、按卷、选章范围导出，并可选追加全书设定库附录。
- **导入导出 API 与界面打通 (`app/api/io_export.py`, `static/js/pages/io.js`)**：
  - `/api/export` 接口全面放行并支持 `format="epub"`；
  - 前端导出配置面板增加“EPUB 电子书”卡片，包含专属目录图标与掌上阅读器排版介绍；
  - 导出历史下载与重试链路无缝兼容。
