## 1. 核心需求与交付内容

依据 `C:\Users\shouj\.kimi_openclaw\workspace\moyu-update-module-plan.md`，在**严格保证内容与数据安全（更新前强制 SQLite 快照备份至 `data/backups/`，绝不改写或删除用户数据）、纯原生 JS 无构建链路、全端触控规范（≥44×44px）与 Minimalist Ink 墨水书斋设计语言**的前提下，完成「软件自动更新」模块的端到端实现：

### 1.1 数据持久层扩展（`app/db.py`）
- 在 `DEFAULT_SETTINGS` 键值字典中注册 5 个自动更新配置项，继承 SQLite3 裸库零开销架构，**无需执行复杂数据表迁移，开箱即用**：
  - `update_channel`：更新通道，默认 `"stable"`（稳定版），可选 `"beta"`（尝鲜测试版）；
  - `update_auto_check`：自动检查策略，默认 `"1"`（进入设置页自动静默探测）；
  - `update_last_check`：记录上次成功执行版本检查的时间戳；
  - `update_skipped_ver`：用户主动跳过的目标版本号（防反复弹窗打扰）；
  - `update_mirror`：GitHub 镜像加速代理前缀（如 `https://ghproxy.net/`），化解国内网络访问 GitHub Releases API 与资源的超时痛点。

### 1.2 服务端 API 与版本引擎（`app/version.py`, `app/api/update.py`）
- 新建独立版本常数模块 `app/version.py`（定义统一版本号 `APP_VERSION = "1.4.0"`），并在 `app/api/__init__.py` 及 `build_exe.py` 中建立单一可信源；
- 新增独立更新路由模块并在 `app/api/__init__.py` 注册，包含以下核心能力：
  - **纯函数语义化版本比对（Semver Engine）**：
    - `clean_version_str`：规范化清理前缀与空格（如 `v1.4.0` → `1.4.0`）；
    - `parse_version`：解构主版本、次版本、修订版本及预发布标签；
    - `compare_versions` / `is_newer`：实现多级数值比较与正式版/预发布版优先级判定；
  - **10 分钟防抖内存缓存（Cache Engine）**：
    - 对频繁检查进行 600 秒内存缓存保护，支持 `?force=true` 强制刷新，规避设置页因外部 API 延迟导致阻塞；
  - **部署形态自适应检测（Environment Detector）**：
    - `detect_environment()` 自动判别 `desktop`（Windows 原生 WebView2）、`docker`（容器环境）、`systemd`（Linux 守护进程）与 `source`（源码运行）；
  - **接口矩阵**：
    - `GET /api/update/check`：比对本地与远端版本，提取最新发布日志、安装包直链及发布时间；
    - `POST /api/update/skip`：记录用户跳过版本，并原子失效缓存；
    - `POST /api/update/apply`：**VPS 一键安全更新入口**。桌面端与 Docker 容器环境下自动拦截并给出指引；在可更新环境下触发后台异步线程，更新前先完整备份数据库至 `data/backups/moyu_pre_update_<timestamp>.db`，再执行 `git pull` 与依赖安装，并由 systemd 触发平滑重启；
    - `GET /api/update/status`：实时向前端汇报后台更新任务进度条、状态与日志。

### 1.3 前端设置页交互与三态呈现（`static/js/pages/settings.js`）
- 在「系统设置」页新增「**软件更新**」独立卡片区块（`section("refresh", "软件更新", ...)`）：
  - **配置网格**：更新通道下拉框、自动检查策略下拉框、GitHub 镜像加速代理输入框；
  - **动作栏**：带有图标与动画旋转状态的「检查新版本」按钮（满足 ≥44×44px 触控热区规范），伴随上次检查时间戳；
  - **结果动态三态渲染**：
    - **状态 1（已是最新）**：墨色绿意圆标与「当前已是最新版本」，清晰提示当前运行良好；
    - **状态 2（发现新版）**：展示新版本徽标、发布日期、带可滚动样式的高密度更新日志展示区；
      - 桌面端：提供「查看 GitHub 发布详情」、「下载 Windows 安装包 (.exe)」与「跳过此版本」；
      - VPS 模式：提供「立即在 VPS 执行一键更新」按钮与动态轮询进度条（包含备份、拉取、安装全流程状态反馈）；
      - Docker 模式：呈现 Watchtower 容器隔离与安全提示；
    - **状态 3（检查失败）**：友好阐明原因，给出国内配置镜像加速代理（如 ghproxy）的具体下一步指引与「重试检查」按钮。

## 3. 改动边界与已知事项

1. **更新包代码签名**：Windows 桌面客户端生成的 exe 为开源社区构建，在未购买 OV 商业证书前若通过应用内静默下载易被 Windows SmartScreen 提示“未知发布者”，因此 v1.4.0 采取「引导式下载」机制，交由用户通过浏览器下载，最为稳妥安全。
2. **数据零破坏原则**：无论桌面端手动覆盖升级还是 VPS 一键拉取升级，用户数据库均存储在 `data/` 目录且更新前自动创建带时间戳的 `moyu_pre_update_*.db` 备份，保证即便更新中断也可无损回退。
