## 一、问题根因与精准定位总结

针对实机环境测试反馈的四项关键问题，本次开发实施了深度追踪与根因定位：

1. **“剧情时间线”报错：`页面加载失败：Can't find variable: outlineTree`**
   - **根因**：`static/js/pages/timeline.js` 中 `outlineTree` 声明在 `try { ... }` 内部，外部第 26 行访问导致变量越界 ReferenceError。
   - **修复**：将 `outlineTree` 提升至顶层作用域与 `work, works, events, tree` 一并声明，彻底杜绝死区。

2. **“写作工作流”报错：`同步失败：Can't find variable: run`**
   - **根因**：`static/js/pages/workflows.js` 的 `showAssetSyncModal` 内部引用了未定义的 `run`（该函数形参仅有 `runId`）。
   - **修复**：后端 `sync_step_assets` 返回显式 `work_id`，前端统一读取 `res.work_id`，安全触发 `entity:changed` 与 `plot.notifyChanged` 事件总线。

3. **“万象谱”角色设定档案中“身份/性格/背景/目标与变化”信息为空**
   - **根因**：`app/workflow_assets.py` 提取角色卡时仅将列表拼接为普通文本放入 `content`，未解析结构化属性，导致 `fields_json` 为 `{}`；万相谱前端只认 `fields_json.identity/personality/background/goal`。
   - **修复**：
     - 后端提取器精准识别身份/性格/背景/目标四维属性并填充至 `fields_json`；
     - 实体写入数据库时支持字典与 JSON 字符串无缝序列化，增量更新时智能合并字段；
     - 前端万相谱（`entities.js`）增加从 `content` 智能回填容错机制，存量与增量角色双向保障。

4. **“万象谱”中“章节引用与登场记录”工作流同步未自动关联**
   - **根因**：
     - `app/workflow_assets.py` 原代码仅在全新创建实体分支写入了 `chapter_entities`，库内已有实体分支完全遗漏；
     - 工作流实例未绑定章节时无兜底解析；
     - 前端同步看板未提供目标章节关联选择器。
   - **修复**：
     - 后端无论实体是新增还是已有，统一写入 `chapter_entities`；
     - 支持显式传入 `chapter_id`，未传时自动基于实例绑定章节或作品首章兜底；
     - 前端同步看板增加「章节登场与引用绑定」选择器，支持作者直观指定与确认。
