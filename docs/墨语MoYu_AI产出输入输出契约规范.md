# 墨语 MoYu 资产中枢功能详解与 AI 产出输入输出契约规范（提案）

> **版本**：v1.0（提案，未动代码）　**日期**：2026-10-09　**基线**：`git HEAD 7113351`（v2.0.0）
> **问题来源**：写作工作流各步骤输出无统一格式 → 步骤间引用靠截断原文 → 抽取器启发式误吸标题行 → 脏数据经资产中枢原样分发给消费方

---

## 第一部分　资产中枢现有功能详解

`app/services/asset_hub.py`（333 行，6 个公开函数）。它的定位是**绑定契约与读写收口**，注意：**它不做内容净化**——这是本次问题的关键认知。

| 函数 | 职责 | 关键行为 | 现有限制 |
| :--- | :--- | :--- | :--- |
| `resolve_binding()` `:10` | 双键互派生与合法性校验 | 只给 `outline_node_id` → 反查补 `chapter_id`；只给 `chapter_id` → 取该章节**首个**大纲节点（`:32 ORDER BY id LIMIT 1`）；两键都给时校验归属同一作品 | 多节点绑同章时只取第一个（D6 遗留）；非法键抛 `ValueError` |
| `upsert_foreshadow()` `:60` | 伏笔幂等写入 | 幂等键＝`work_id + title + 绑定键`（`:80-90`）；命中则**仅在 content 非空时补写**（`:95-99`，用 `COALESCE(NULLIF(...))` 不覆盖已有内容）；返回带 `_is_new` | **只做 `.strip()`**，不校验标题是否为套话/标题行；`title` 截断无长度上限 |
| `upsert_timeline_event()` `:125` | 时间线事件幂等写入 | 幂等键＝`work_id + event + 绑定键`（`:146-156`）；未给 `sort_order` 时取 `MAX+1`（`:162-167`）；**命中重复时直接返回，不更新任何字段** | 同上，且事件文本完全不过滤 |
| `aggregate_for_node()` `:192` | 大纲节点聚合读侧（唯一口） | `WHERE outline_node_id=? OR chapter_id=?`（节点有绑章节时，`:207/216`），无绑章节时退化为单键 | 只管"查得全"，不管"查出来的是不是脏数据" |
| `aggregate_for_chapter()` `:255` | 章节聚合读侧（唯一口） | 先取该章节全部大纲节点，`WHERE chapter_id=? OR outline_node_id IN (...)`（`:265-283`） | 同上 |
| `detach_chapter()` `:315` | 删前影响面与安全解绑 | 统计伏笔/事件/节点三类数量 → 全部 `SET NULL` → 返回 `total`（`:317-333`） | 只解绑不转移，只绑章节的产物会失去可见性（R-3） |

**一句话概括**：资产中枢解决的是"**绑得对、不重复、查得全、删得明**"，它**不解决"内容对不对、干不干净"**。清洗职责目前无人承担。

## 第二部分　问题链路诊断（三层缺口）

### 缺口 1：Skill 输出没有统一的机器可解析格式

`app/builtin_skill_data.py` 现有 14 份内置技能手册，抽查其"交付格式"约定：

| 有交付格式约定 | 无交付格式约定 |
| :--- | :--- |
| PROSE_CRAFT、EXPANSION_CRAFT、REWRITE_DIMENSIONS、COMPRESSION_FORMATS、AI_TONE_CATALOG、ANALYSIS_RUBRIC、CREATION_PIPELINE、SCENE_BEATS | STYLE_FINGERPRINT、GENRE_PLAYBOOK、STRUCTURE_MODELS、CONSISTENCY_TAXONOMY、CHARACTER_ARC_MODELS、WORLDBUILDING_CHECKLIST |

**8 有 / 6 无，且"有"的那些格式各不相同**（有的用 `### 扩写稿（纯净版）`，有的用固定报告模板，有的用 markdown 表格）。下游抽取器只能靠启发式猜测，技能一换格式就失效。

### 缺口 2：步骤间引用传的是"截断后的原文"，不是结构化字段

`app/workflow_engine.py:26` 用 `{{steps.N.output}}` 做模板引用，`:29-33` 的 `_truncate_prev()` 对超过 4100 字的前序输出**只保留头 2000 + 尾 2000 字，中段直接砍掉**并插入"……[中段内容已截断]……"。

后果：下一步拿到的是一段**被腰斩的自由文本**，里面混着上一步的套话、标题、正文，模型只能自己猜哪段是有效信息——这就是你观察到的"理解不到位、识别错误"。

### 缺口 3：抽取器把标题行当资产吸收，且格式稍变即漏抽

实测（`extract_structured_assets_from_text`，`app/workflow_assets.py:75`）：

**测试 1——含套话的完整工作流输出：**
```
好的，我已经根据你的要求完成创作。以下是修改后的内容：
### 世界观设定 / ### 伏笔暗线 / ### 时间线（表格+列表）
希望以上内容对你有帮助，如需调整请告诉我。
```
抽取结果：
- `entities: ['伏笔暗线']` ← **章节标题被当成实体入库**（`card_pattern` `:287` 匹配 `### 任意词`）
- `notes: ['世界观 · 设定']` ← 标题被当成世界观设定条目
- `timeline: []` ← **真正的时间线事件一条都没抽到**
- `foreshadows: [('青玉佩的来历', '【回收条件】第三卷揭示身世')]` ← 这条（表格）抽对了

**测试 2——格式变体（同一条事件，四种写法）：**

| 写法 | 抽取结果 |
| :--- | :--- |
| `### 时间线` + `- 开元三年：顾风下山` | 空（冒号不匹配，要求 `·` 分隔） |
| `开元三年 · 顾风下山`（无标题无列表符） | 空 |
| 套话开头 + 正文段落 | 空（好现象：套话本身没被吸收，但正文也没抽到） |
| 正文段落中间夹套话 | 空 |

**结论**：抽取器只认极窄的固定形态（`【时间线】`/`【剧情事件】` 前缀 + `·` 分隔），**格式一变就全漏**；同时 `### 任意标题` 无条件被当成档案卡 → **标题字符被当成资产吸收**。两种失效叠加，就是你看到的"该收的没收到，不该收的收了一堆标题"。

**根因**：`clean_str()`（`:71`）只做了 `re.sub(r'[*#_\`]', '', s).strip()`——它只是**抹掉 markdown 标记符号**，既不识别"这是标题行"，也不识别"这是 AI 套话"。

### 缺口 4：净化缺失导致脏数据直达消费方

链路是：`AI 原文` → `extract_structured_assets_from_text()`（启发式）→ 前端勾选 → `sync_assets_to_database()`（`:526`，直接调 asset_hub 落库）→ 消费方（大纲/工作台上下文/看板/时间线/审校）。

**整条链路上没有任何一层负责"这份内容是不是该入库的资产"**。所以"以下是修改后的内容"这类文本，只要形态上够得上某条正则，就会被写成伏笔/事件/设定，再被消费方原样展示和喂给模型。

## 第三部分　契约规范提案（"AI 产出输入输出契约"）

### 3.1 输出契约：规定 AI 侧必须怎么交（约束在提示词层）

所有会产出资产的技能与工作流步骤，输出必须遵守三段式：

```
【正文/正文产物】            ← 唯一给人类看的内容，可含任意文字
<!-- MOYU:ASSETS
{
  "entities":   [{"name":"", "category":"", "content":"", "tags":""}],
  "relations":  [{"from":"", "to":"", "label":""}],
  "timeline_events": [{"time_label":"", "event":"", "characters":""}],
  "foreshadows":[{"title":"", "content":"", "status":"planted"}],
  "outline_nodes": [{"title":"", "synopsis":"", "parent_id":null}]
}
MOYU:ASSETS -->
```

规则：
1. **资产一律走机器可读的 JSON 块**，不再从正文里靠正则猜；正文中允许存在任意套话与标题，不影响抽取。
2. **JSON 块缺失或解析失败时，回退到现有启发式抽取**，并在 UI 上标注"低置信度，请人工核对"——不静默入库。
3. **Skill 手册补齐统一交付段**：现有 6 份无格式约定的手册需追加"产出资产时按 MOYU:ASSETS 块提交"的说明。

### 3.2 净化层：新增 `app/services/output_normalizer.py`（核心新增）

四个能力，挂在抽取之前：

| 函数 | 做什么 | 规则来源 |
| :--- | :--- | :--- |
| `strip_ai_chatter()` | 删除开篇/收尾套话 | 套话词表：以下是、如上所述、好的、希望以上、如需调整、这是为您、请注意、修改后的内容、供你参考……（前缀/后缀匹配 + 整行删除） |
| `strip_heading_only_lines()` | 删除"纯标题行"（只有 `### xxx` 没有内容的行） | 防止 `### 伏笔暗线` 被当实体 |
| `extract_assets_block()` | 优先解析 `MOYU:ASSETS` JSON 块 | 解析失败降级 |
| `sanitize_asset_item()` | 单条资产校验 | 标题 ≤30 字、不含标题符号、不在套话词表内、不含 `[中段内容已截断]` 标记、非纯标点 → 不通过则丢弃并计数 |

### 3.3 步骤间引用改造（解决"上一步喂给下一步理解不到位"）

`app/workflow_engine.py`：
- 引用 `{{steps.N.output}}` 时，**同时提供 `{{steps.N.assets}}`**（结构化资产摘要）与 `{{steps.N.summary}}`（该步结论摘要）。
- `_truncate_prev()`（`:29`）改为：**正文截断照旧，但结构化字段全量传递**——避免有效信息被腰斩。
- 模板渲染时给下一步明确标注"以下是上一步的结构化产出（可信），以下是原文片段（可能含套话，仅供文风参考）"。

### 3.4 资产中枢加固（让 hub 拒绝脏数据，而不只是接收）

在 `upsert_foreshadow` / `upsert_timeline_event` 入口增加：
- 调用 `sanitize_asset_item()`，不通过直接丢弃并在返回值标记 `_rejected: true` + 原因；
- `sync_assets_to_database()`（`:526`）汇总 `rejected` 数量返回给前端，UI 提示"已过滤 N 条无效条目"。
