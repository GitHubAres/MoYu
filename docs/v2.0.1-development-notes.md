## 一、本次迭代目标与里程碑

墨语 MoYu 正式发布 **v2.0.1** 版本。本版本重点落地了 **AI 产出输入输出契约系统** 以及 **全链路脏数据拦截与可视化预警机制**，彻底解决长篇小说 AI 创作过程中套话污染资产库、纯标题误识为实体、前序步骤长文本截断导致的资产腰斩，以及脏数据静默入库等关键顽疾。

---

## 二、功能特性与技术实现亮点

1. **AI 输出净化与标准化层（app/services/output_normalizer.py）**：
   - **套话分级清洗**：构建分级套话词表（强套话词表与弱套话词表），实现 strip_ai_chatter。在 AI 产出提取场景采用严格模式（strict=True），而在用户合法正文保留弱套话避免误伤。
   - **纯标题行剥离**：实现 strip_heading_only_lines，精准识别无正文描写的孤立层级标题（如 ### 道具神兵），剥离并自动记录至拒绝列表。
   - **契约块优先抽取**：实现 extract_assets_block，优先提取 <!-- MOYU:ASSETS ... MOYU:ASSETS --> 机器可读标准契约块；仅在缺失时安全降级至启发式正则抽取，并标记低置信度。
   - **单条资产准入校验**：实现 sanitize_asset_item，硬性拦截超长标题、截断标记残留、纯标点符号和套话标题。

2. **工作流步骤间引用升级（app/workflow_engine.py）**：
   - 步骤间引用除 {{steps.N.output}} 外，正式支持结构化字段透传：{{steps.N.assets}} 与 {{steps.N.summary}}。
   - 彻底避免前序步骤长文本在模版装配中被截断时，关键资产元数据同步丢失的问题。

3. **资产中枢写入入口校验加固（app/services/asset_hub.py）**：
   - 资产中枢写入入口（upsert_foreshadow 与 upsert_timeline_event）强制接入 sanitize_asset_item 校验。
   - 脏数据拒绝入库并显式标记 _rejected=True 与具体原因，杜绝静默失败与死锁。
   - 资产批量同步 API 统一回传 rejected_count 与 rejected_items 详情。

4. **前端交互透明化与预警机制（static/js/pages/workflows.js & static/js/ui.js）**：
   - 在步骤执行后发现低置信度（降级启发式抽取）或资产被过滤时，主动展示明确的警告提示（Amber/Warning 级视觉）。
   - Toast 组件新增统一 warn 类型（金色琥珀色高亮并保留 5 秒），确保创作者对数据过滤完全可知可控。

5. **内置技能手册统一交付契约（app/builtin_skill_data.py）**：
   - 内置所有技能手册更新交付段，强制大模型按标准 MOYU:ASSETS 格式输出机器可读资产。
