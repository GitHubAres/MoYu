## 1. 核心需求与完成事项

依据 docs/development-plan.md 专项规划第 8 节《原生桌面客户端（WebView2 接入，消除控制台黑框）》，本版本彻底解决了原 exe 打包形态依赖黑色命令行控制台窗口（CMD/Console）、需手动关闭控制台、关闭后易留下后台僵尸进程、且强制跳出外部浏览器的核心体验痛点：

### 1.1 轻量原生视窗体系接入
- **内核驱动**：引入 pywebview>=5.0，基于 Windows 10/11 操作系统内置的 WebView2 / EdgeChromium 运行时。
- **纯轻量体积控制**：打包后体积仅从 ~33.7MB 增至 39.6MB（增加不足 6MB），相较于动辄 150MB+ 的 Electron 方案，保持极度轻巧绿色、无任何外部 Node.js 运行时依赖。
- **视窗参数调优**：
  - 默认窗口尺寸：1366x820
  - 最小限制尺寸：1024x680
  - 窗口标题：墨语 MoYu - AI长篇小说创作工作台
  - 允许文本选区复制与拖拽操作，全面适配桌面大屏沉浸写作。

### 1.2 进程生命周期与双模兼容拓扑
- **主线程/服务拓扑重构 (moyu_entry.py)**：
  - 主线程专职运行 pywebview.create_window() 与原生事件循环；
  - 后台守护线程（Daemon Thread）托管 FastAPI / Uvicorn 本地 HTTP 服务（127.0.0.1:8321）；
  - 建立服务就绪探测轮询机制（10s 超时保护），在原生视窗渲染前完成端口握手，杜绝启动白屏和连接被拒。
- **生命周期强绑定与僵尸进程清理**：
  - 监听窗体 window.events.closed 关闭事件：当用户点击右上角叉号（×）关闭窗口时，即刻向 Uvicorn 发送优雅停止信号（server.should_exit = True），随主线程一同退出，彻底根除孤儿进程与端口争用。
- **单实例互斥保护**：
  - 启动前探测 127.0.0.1:8321 端口：若检测到已有实例在运行，直接激活唤起已有页面并干净退出当前进程，防止多重运行引发数据库写冲突。
- **双模兼容与异常降级 fallback**：
  - 支持传入 --browser 命令行参数或设置环境变量 MOYU_WEBVIEW=0 / MOYU_BROWSER=1，一键回退到无头服务器 + 外部浏览器模式；
  - 内置完善的异常捕获：若在某些未安装 WebView2 的精简版 Windows 环境中启动窗体失败，自动向 stderr 打印提示并无缝降级回退至系统默认浏览器，绝不闪退或崩溃。

### 1.3 打包工程改造 (uild_exe.py)
- **消除控制台黑框**：
  - PyInstaller 构建配置加入 --noconsole，彻底消除黑框命令行闪烁。
- **隐式导入与运行时资源收集**：
  - 加入 --collect-all webview 收集 JavaScript 原生交互脚本；
  - 补齐 clr、clr_loader、pythonnet、webview.platforms.winforms、webview.platforms.edgechromium 等关键 Windows 原生支持组件；
  - 保持工作区纯净原则：在临时目录注入静态缓存版本戳 ?v=1.2.0，不污染代码库；
  - 构建完成后自动输出 SHA256 校验清单文件与 dist/manifest.json。

---


### 1.4 --noconsole 模式 Uvicorn Formatter 崩溃关键修复
- **根因分析**：Windows 在 --noconsole（无控制台）模式下，sys.stdout 和 sys.stderr 默认解析为 None。Uvicorn 启动时尝试使用 uvicorn.logging.DefaultFormatter，由于缺乏控制台 TTY 输出句柄，抛出严重致命异常：ValueError: Unable to configure formatter 'default'，导致程序弹窗崩溃。
- **深度修复**：
  1. 在 moyu_entry.py 顶层加入标准流保护垫片，当 sys.stdout / sys.stderr 为 None 时安全重定向至 os.devnull / io.StringIO()；
  2. uvicorn.Config 显式设置 log_config=None，彻底关闭无控制台环境下的日志格式化冲突；
  3. 桌面模式单实例逻辑重构：本地若已存在运行实例直接拉起原生窗口，杜绝非预期跳出浏览器。
