**编制日期：** 2026-10-07  
**定位：** 预设 Skill 输出规格规范化 · 写作工作台新实体与未入库类别信息智能识别与确认入库 · 跨模块全闭环联动

## 一、问题审核与现状诊断

### 1. 预设 Skill 输出规格与下游模块契约不对齐
- **现状**：
  现有 13 项内置 Skill（如 `default-outline`, `novel-premise`, `novel-world`, `novel-cast`, `novel-scene`, `novel-forge` 等）在创作方法论上详尽完备，但在最后的交付输出阶段：
  - 缺乏标准化的 Markdown 结构化标签（如【人物】、【道具】、【地点】、【势力】、【法则】、【时间线事件】、【伏笔】）；
  - 表格表头未严格约束为下游解析器（`app/workflow_assets.py`）最优匹配的列名（如“角色 | 定位 | 欲望”、“关系对 | 表面关系 | 核心冲突”等）；
  - 导致用户在执行 Skill 产生精彩构思后，无法一键导入“万相谱”实体库、故事大纲树、时间线及伏笔看板中，必须手动二次搬运。
- **审核结论**：
  **在坚决不改变原有 Skill 功能、创作逻辑、思考流派与核心步骤的前提下**，对技能的“交付/输出格式”章节进行规范化增强，补充清晰的“结构化资产交付规范”，让 AI 在输出自然语言创意的同时，规范使用标准标记与表格。

### 2. 写作工作台缺乏“未入库类别信息自动识别与确认入库”闭环
- **现状**：
  写作工作台当前仅有针对“已存在实体”的反向探测（`detectEntitiesInContent` 只能在文中匹配已存在于 `allEntities` 的条目并打勾关联），如果作者在正文或 AI 伴写生成中引入了全新的角色名、新法宝、新门派、新地名或新设定，系统毫无感知，设定库无法随正文实时生长。
- **审核结论**：
  必须为写作工作台增加正文实体正向提取与差集探测能力：
  - 智能识别文章中尚未收录于当前作品任何类别库（万相谱实体库、伏笔库等）的新名称与类别信息；
  - 严格遵循内容安全红线：**不得静默改写或静默入库，必须弹出交互面板供作者预览、核对分类、勾选确认后才写入数据库**；
  - 入库后自动关联当前章节，并实时广播 `entity:changed` / `plot:changed` 事件，驱动全局 Store、万相谱与上下文栏即时同步。

## 三、四大执行阶段与行动计划

### 阶段一：预设 Skill 交付规范规范化对齐 (Prompt Specification Alignment)
1. **审查并优化 `app/db.py` 中的 `BUILTIN_SKILLS`**：
   - 保持前序交互和核心步骤完全不变；
   - 重点规范以下技能的交付模板（Delivery Template）：
     - `novel-cast`：明确交付输出标准人物档案卡（`### 角色名` 或 `【人物】`）与标准冲突关系网表（`| 关系对 | 表面关系 | 核心冲突 |`）；
     - `novel-world`：明确规范输出势力表（`| 势力 | 定位 | 宗旨与领袖 |`）、地点表（`| 地点 | 归属 | 特征与危险 |`）、道具法宝表（`| 道具 | 品阶 | 功能与代价 |`）及法则条目（`【法则】`）；
     - `default-outline`：统一卷纲（`第X卷 卷名`）、章纲（`第X章·章名`）、时间线事件（`【时间线事件】：时间：...，事件：...，人物：...`）与伏笔计划表（`| 伏笔 | 埋设 | 揭示 |`）；
     - `novel-premise`：统一立项书中的题材、一句话简介、核心看点及主角/主要对手标准化标签；
     - `novel-scene`：统一场景细纲（`第X节：场景名`）与场景内时间线/伏笔标记。
2. **增强资产提取器泛化能力 (`app/workflow_assets.py`)**：
   - 支持更多常用表头别名（如“门派/帮派”、“神物/秘籍”、“场景/世界”）；
   - 优化行级标签与括号别名提取正则，防止遗漏。

### 阶段二：后端未入库实体探测与批量入库服务 (Backend Detection & Intake Service)
1. **新增未入库实体智能探测接口**：
   - `POST /api/works/{work_id}/entities/detect-unregistered`：
     - 输入：`{ "content": "正文文本", "chapter_id": 123 }`；
     - 逻辑：
       - 利用显式结构化标记、专名提取模式在正文中探测候选实体（人物、道具、地点、势力、法则）；
       - 获取当前作品已有实体集合（名称与别名全集）；
       - 计算差集，自动剔除停用词与重复词；
       - 返回 `{ "unregistered": [ { "name": "...", "category": "...", "snippet": "...", "tags": "..." } ] }`。
2. **新增/完善批量快捷入库接口**：
   - `POST /api/works/{work_id}/entities/batch-intake`：
     - 接收用户在前端弹窗中勾选并编辑确认的实体列表；
     - 原子化写入 `entities` 表，并可选关联 `chapter_id`；
     - 返回新增条目统计与实体详情。

### 阶段三：写作工作台新实体发现与确认入库 UI (Workbench Interactive Intake)
1. **写作工作台轻量探测条**：
   - 在写作台编辑器底部或上下文抽屉中提供「设定探测」状态，在正文变动防抖或用户主动点击时探测未入库实体；
   - 若检测到未入库实体，展示优雅的微提示：“发现 X 个未收录设定（如【法宝】太虚残剑） [查看并入库]”。
2. **「确认入库」交互弹窗 (Intake Modal)**：
   - 弹窗展示待入库实体卡片，包含类别选择器（人物/道具/地点/势力/法则）、实体名称、上下文引文、标签输入框；
   - 支持全选/反选与行内快速调整；
   - 用户点击「确认入库」后提交，系统即刻写入数据库并自动关联当前章节；
   - 触发 `window.store.events.emit("entity:changed")` 和 `plot:changed`，同步更新本地 `allEntities`，实现零刷新无缝衔接。

### 阶段四：全链路跨模块验证、回归与发布 (Verification & Release)
1. **编写端到端自动化测试**：
   - `tests/test_skill_spec_and_entity_intake.py`：
     - 验证预设 Skill 输出范例文本可 100% 被 `workflow_assets` 结构化提取；
     - 验证 `detect-unregistered` API 正确识别文章中的新实体并精准过滤已有库；
     - 验证 `batch-intake` 确认入库后，万相谱与章节关联一致性；
2. **全量回归测试**（确保全部已有测试 100% 通过）；
3. **版本升级至 v1.9.2**，归档开发说明产物，推送 GitHub 并热部署至生产 VPS。
