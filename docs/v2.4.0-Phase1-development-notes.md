## 一、 核心开发背景与网文作者痛点

在商业网文高强度创作场景下，长篇章节的 AI 续写/扩写单次生成耗时较长（通常在 10s - 30s 之间）。在非流式或粗颗粒流式模式下，作者面临以下突出问题：
1. **反馈迟滞与黑盒焦虑**：模型生成期间界面无字数进度 ticker，作者无法判断生成速度与方向是否偏离；
2. **缺乏即时视觉打字机节奏**：没有沉浸式的墨色打字机呼吸光标与动态滚动伴随；
3. **中断机制代价高**：过去一旦点击停止，往往丢失已生成的半截优秀文字，导致作者灵感浪费；后端流式断开时，若没有严格的 `CancelledError` 兜底，任务台账容易长久挂起为 `running` 状态；
4. **多候选顺序与字数统计失真**：多候选并发生成时字数与 token 统计未做精细累计。

## 二、 Phase 1 落地能力与模块清单

### 1. 后端 SSE 稳健流式通道与任务台账容错 (`app/features.py`)
- **连接头增强**：在 `/api/ai/generate` 的 `StreamingResponse` 中补充关键响应头：
  - `Cache-Control: no-cache, no-transform`
  - `Connection: keep-alive`
  - `X-Accel-Buffering: no`（彻底杜绝 Nginx 反向代理层对 SSE 缓冲导致的卡顿）
- **实时 Token 与字数汇算**：修复多候选流式生成时的 token 汇总统计，确保每个候选的分块 usage 能正确累计到后台台账中。
- **客户端断开与异常中断守卫 (`CancelledError` / `GeneratorExit`)**：
  - 当网文作者主动中止（前端发送 `AbortController.signal`）或连接中断时，捕获异常并提取当前已生成的候选文本。
  - 若已生成有效片段，将台账标记为 `status='done'` 附带 `aborted=True` 标志和真实消耗 token 与耗时，杜绝孤儿 running 任务。
  - 若一字未产出即被取消，安全调用 `cancel_task(task_id)`。

### 2. 前端打字机实时上屏与字数跑表 (`static/js/pages/workbench.js`)
- **即时字数跑表**：候选卡标题区新增独立的字数统计胶囊（`0 字` → `实时递增`），根据过滤空白符后的字符数动态计算并展示。
- **一键停止交互与优雅降级**：
  - 侧边栏主面板与卡片右上角均提供醒目停止按钮。
  - 点击停止后，前端触发 `abortCtrl.abort()`，弹出友好提示：`"已按要求中止 AI 正文流式生成，保留已产出片段"`。
  - 中止后，卡片保留已打出的全部正文，并自动在状态栏打上 `[已中止]` 标签，解除打字机光标，立即展示【采纳】、【预览差异】、【复制】、【重试】等动作按钮，作者可随时将已生成的优质半截文本一键采纳到编辑器中。

### 3. 视觉与排版设计系统更新 (`static/css/app.css`)
- **墨韵打字机光标**：更新 `.streaming-caret::after` 样式，采用墨语设计系统黛青底色 `#1B2A38`（深色模式下采用透亮天蓝 `#93C5FD`），配置 `typewriter-pulse` 优雅纵向缩放与呼吸投影动画，还原古典文人书斋打字机的沉浸书写感。

### 4. 自动化回归测试套件 (`tests/test_stream_typewriter.py`)
- 覆盖 3 项全新用例：
  1. `test_ai_generate_streaming_success`：验证完整 SSE delta 流式分块、done 帧与后台台账闭环；
  2. `test_ai_generate_streaming_multi_candidates`：验证多候选顺序与 token 累加统计；
  3. `test_ai_generate_streaming_error_handling`：验证上游模型异常时的 error 帧与状态容错。
