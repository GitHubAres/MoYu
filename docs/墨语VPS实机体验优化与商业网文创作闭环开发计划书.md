## 一、 优化目标与核心边界

根据在 Linux VPS 实机创作网文爆款小说《镇魔狱：开局吞噬天魔道果》（作品ID: 42）以及执行工作流一键反哺入库的实测结果，系统虽然实现了从立项构思到两章成文的工业化闭环，但在数据一致性、网文特色工具及反哺纯净度上暴露了关键缺陷。

本开发计划聚焦于将墨语打造成真正契合网文作者实操体验的“硬核连载武器”：

1. **核心任务一：大纲去重与 Markdown 标题清洗**
   - 彻底修复大纲提取算法中因 Markdown 加粗 `**` 或同名卷导致生成重复卷节点（如出现 ID 335 与 ID 339 卷节点重合）的缺陷。
2. **核心任务二：资产反哺隔离与防污染（万相谱 vs 创作备忘）**
   - 解决泛化设定与方法论笔记（如“前三章节奏控制”、“立项核心设定”）被粗暴转为 `term` 实体的问题。
   - 规范 `notes` 归属或过滤，提供干净的万相谱字典，保障后续 AI 上下文装配纯净度。
3. **核心任务三：Schema 统一与健壮性防护**
   - 统一大纲节点、伏笔及版本记录的表字段调用契约，消除 `is_volume`、`description` 等不存在列的冗余逻辑与潜在崩溃隐患。
4. **核心任务四：商业网文特色——主角金手指/状态面板 (Protagonist State Sheet)**
   - 网文极度依赖主角金手指的数值成长与状态记录（如吞噬道果熟练度、已夺寿元、当前功法层级）。
   - 为作品提供可结构化记录与 AI 装配的“主角状态板”，免去作者便签记账痛苦。
5. **核心任务五：全功能真人模拟实机验证与终版报告归档**
   - 编写自动化实机回归流水线，模拟真人作者全链路测试：热榜灵感 ➔ 故事立项 ➔ 大纲生成 ➔ 正文撰写 ➔ 资产反哺入库 ➔ 状态面板查看。
   - 输出正式交付报告与测试报告。

## 二、 详细里程碑分解

### 阶段一：资产反哺数据清洗与大纲去重修复 (M1)
- **文件**：`app/workflow_assets.py`, `app/services/plot_service.py`
- **任务**：
  1. 优化 `extract_structured_assets_from_text()` 中的大纲解析：自动剥除标题首尾的 `**`、`#` 及空字符；
  2. 大纲节点入库前执行严格标题归一化与父子节点查重，若已有同名卷节点，则更新其概要而非作为新节点插入；
  3. 过滤并合理分流创作笔记类实体，禁止将方法论（如包含“节奏控制”、“核心设定”）作为术语盲目插入 `entities` 表；
  4. 校验并确保与 SQLite 数据库 Schema 字段契约 100% 保持一致。

### 阶段二：主角状态与金手指看板 (M2)
- **文件**：`app/api/protagonist.py`, `app/db.py`, `app/services/context_service.py`
- **任务**：
  1. 支持主角数值/状态记录（修为境界、金手指数值、关键法宝、当前悬念卡点）；
  2. 支持将主角状态一键作为专属上下文注入到正文创作 Prompt，避免设定跑偏。

### 阶段三：VPS 实机同步与真人全流程模拟测试 (M3)
- **任务**：
  1. 部署改动至 VPS 生产环境；
  2. 模拟真实作者执行端到端创作流，验证修复效果；
  3. 运行全量回归测试套件。

### 阶段四：交付说明与终版报告归档 (M4)
- **任务**：
  1. 按照 AGENTS.md 规范归档 `docs/v2.3.0-development-notes.md`；
  2. 输出实机全功能测试验收报告。
